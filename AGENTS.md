# AGENTS.md: Magic Editor X

Contract for coding agents (Claude Code, Codex, Cursor) working on this repository. The README is the user manual; this file is the exact technical contract. When code and this file disagree, fix one of them in the same change.

## Rules

- **Docs first.** Before using any package or Strapi API, read the documentation and the installed types of the version in `package-lock.json` (Editor.js 2.31 and its tools, Yjs 13.6, Socket.IO 4.8, Strapi 5.61, Design System 2.2.4, styled-components 6, zod 4). Record what you read in the commit or PR.
- **Lint as configured.** `npm run lint` and `npm run format:check` must pass before every commit. No new `eslint-disable` without a one-line reason; never weaken the config.
- **Maintained packages only.** Check release activity before adding a dependency. Keep the versions the Strapi admin provides (React 18, react-dom 18, react-router-dom 6, react-intl 6, styled-components 6, `@strapi/design-system` and `@strapi/icons` 2.2.x).
- **Free software.** There is no license, tier, quota or upgrade logic and no telemetry. Do not add any. The plugin makes outgoing requests only for link previews, image by URL, the external link check and the AI provider and LanguageTool server the owner configured.
- **Security.** Every admin route has `admin::isAuthenticatedAdmin` and `admin::hasPermissions` with the actions below; handlers that touch a document check Content Manager access through `services/access.js` and answer 404 when it is denied. Validate input with strict, bounded zod schemas. Never log content, tokens, keys, URLs with queries, user ids or email addresses. Never return secrets.
- **Compatibility.** Stored block names and data shapes must keep working. A change to a stored shape needs a migration in `server/src/services/migrations.js` and tests with real-shaped fixtures.
- **Synthetic data only** in tests, fixtures and screenshots (`*.example.test`, RFC 5737 addresses).

## Field

- Custom field uid `plugin::magic-editor-x.richtext`, type `json`. Options in the Content-Type Builder: `options.placeholder` (text), `options.minHeight` (number, 120 to 2000) and the field preset options below.
- Value: Editor.js document `{ time, blocks: [{ id, type, data, tunes? }], version }`, stored as an object. `null` means empty.
- `shared/editor-data.mjs` `normalizeEditorData(value)` keeps a valid top-level `fieldKey` (2.4, see Field identity) and accepts objects, 1.x JSON strings, double-encoded strings, plain text or HTML strings and bare block arrays. It gives blocks without an id a deterministic id, drops invalid blocks and prototype-polluting keys, and throws `EditorDataError` (`TOO_LARGE`, `TOO_MANY_BLOCKS`, `TOO_DEEP`, `INVALID_SHAPE`) above 5 MiB, 5000 blocks or depth 24.
- `shared/sanitize-policy.mjs` `BLOCK_POLICIES` defines the stored data of every built-in block (the README has the table). Code-registered blocks (custom block SDK, see below) are cleaned by their definition's schema. Other unknown block types (Settings custom blocks, blocks whose definition was removed) go through a generic policy: strings are inline HTML, keys named `url`, `href`, `link`, `src`, `photo`, `source` or `embed` are URLs. Tunes: `alignmentTune`, `textVariant`, `indentTune`.
- `register.js` adds a Document Service middleware: on `create` and `update` every Magic Editor X field (also inside components and dynamic zones) is replaced with `cleanEditorValue(value, { rawHtml, inlineTags })` and checked against its preset. Invalid values throw `ValidationError` (400) with `details: { code, errors: [{ path, message, name }] }` (`errors` lets the Content Manager show the reason on the field; `utils/form-errors.js`).
- Table of contents (2.3): block `toc` with data `{ title (plain text, max 200), minLevel, maxLevel (1-6, min <= max, defaults 2 and 4), style: 'ordered'|'unordered', _mex: 1 }` (built-in marker, see Media Library blocks > Compatibility). Only the settings are stored; the entries are built from the headings when the content is rendered (`shared/toc.mjs`). The editor tool (`tools/toc.js`) shows a read-only live preview from the headings in the editor (MutationObserver on the block area, so typing, level changes, undo and collaborators' edits update it).
- Mentions (2.3): an internal link with a flag, `<a href data-mex-uid data-mex-document-id data-mex-locale data-mex-mention="true">Title</a>`. `data-mex-mention` is one of `INTERNAL_LINK_ATTRIBUTES`; `cleanInternalLinkAttributes` keeps it only with a valid uid and documentId and normalises it to `"true"`. Everything that applies to internal links applies to mentions (presets `linkTargets`, link check, `resolveHrefs`, API resolution).
- Code languages: `shared/code-languages.mjs` `CODE_LANGUAGES` is the list the editor offers; the admin loads one Prism grammar per id (`tools/prism/index.js`, checked by `tests/structure.test.mjs`) and the renderers write `language-<stored value>`. The policy keeps any `/^[a-z0-9+#-]{1,32}$/i` value (content from other tools keeps its language; the editor shows it as an extra option, highlighted as plain text). The editor maps 1.x aliases (`js`, `html`, ...) to the canonical id when the block is edited.
- Image data may carry `decorative: true` and `focalPoint: { x, y }` (0..1, rounded to two decimals; `cleanFocalPoint`); `simpleImage` keeps `alt` and `decorative`.
- Media Library blocks (2.3, `shared/sanitize-policy.mjs`):
  - `gallery`: `{ images: [{ file, caption, decorative?, focalPoint? }] (max 50, `MAX_GALLERY_IMAGES`), layout: 'grid'|'carousel', columns: 1-6 (default 3), caption }`; `file` is an image file like the image block (`url`, `id`, `documentId`, `alt`, `mime`, `name`, `hash`, `ext`, `width`, `height`, `size`, `formats`); entries without a usable URL or with a non-`image/*` MIME type are dropped.
  - `video`: `{ file, poster?, title (max 200), caption, loop, muted, tracks }`; `audio`: `{ file, title, caption, loop, tracks }`. `file` (`cleanMediaFile`: url, id, documentId, mime, name, hash, ext, width, height, size) must have a `video/*` or `audio/*` MIME type when one is stored, else its URL is emptied and nothing renders; `poster` is an image file. `tracks` (max 8, `MAX_MEDIA_TRACKS`): `{ file, kind: captions|subtitles|descriptions|chapters, srclang (BCP 47 or ''), label (max 100), default? }`; the file must be WebVTT (`text/vtt`, `.vtt`); at most one `default`. Controls are always rendered; there is no autoplay.
  - Compatibility (contract: stored data of a custom block named like a 2.3 built-in block is never rewritten or stripped): before 2.3 a Settings custom block could be named `toc`, `gallery`, `video`, `audio` or `synced` (or `mention`, now an inline tool). `shared/built-in-marker.mjs` (re-exported by `sanitize-policy.mjs`): `MARKED_BLOCKS` (per type the data keys and the anchor key + JSON type: gallery `images` array, video/audio `file` object, synced `ref` string, toc none), `BUILT_IN_MARKER` = `'_mex'`, `BUILT_IN_MARKER_VERSION` = 1. `isBuiltInBlock(block)` for these types: data with `_mex` a positive integer is built-in; otherwise built-in only with exactly the built-in shape (only `MARKED_BLOCKS` keys, anchor present with its type; toc any subset, also `{}`). Custom block data never has that shape (simple blocks always store `content`, `blockType`, `blockName`; embedded-entry blocks `entry`, `contentType`, `displayMode`; field names cannot start with `_`). The policies of the five types always write `_mex: 1` (so every stored built-in block carries it and older renderers keep recognising newer data); the built-in admin tools are wrapped by `tools/marked.js` `markedTool` (saves add the marker; data that is not built-in is kept exactly and shown as the Editor.js stub). Everything type-specific goes through `isBuiltInBlock`/`isMarkedBuiltIn`, never `BLOCK_POLICIES[type]` or a bare type check: sanitiser, renderers (`prepareBlocks` `known`, `annotateHeadings`), quality (toc, media rules), references, find and replace (no fields for custom blocks), diff (`leafKind(block, …)`; a `_mex`-only change is not a change), `computeStats`, `imageHasAlt`, synced helpers, the Yjs guard (only built-in synced data must be exactly `{ ref, _mex? }`) and the schema `if` condition. New custom blocks cannot use these names (server `LEGACY_BUILT_IN_NAMES`, admin `LEGACY_NAMES`; `toc` and `mention` are no longer in `RESERVED_NAMES`, so a stored block keeps validating); an existing block keeps its name on update, and its own editor tool replaces the built-in one (`buildTools` `LEGACY_CUSTOM_NAMES`; with a custom block named `mention` the mention inline tool is registered as `mention$mex`). Tests: `tests/reserved-names.test.mjs` (against 2.2.0 output in `tests/fixtures/reserved-names-2.2.json`), `tests/integration/reserved-names.test.mjs`. A change to `BLOCK_POLICIES` needs the matching change in `shared/schema.mjs` (then `npm run schema`), `types/index.d.ts` and the renderers; `tests/schema.test.mjs` enforces it.

## Tables v2 (2.4)

Same block type `table`, same 2.3 keys; four optional keys. `shared/table.mjs` holds every rule (policy core, layout, live-guard shape check, editor model). No routes, permissions or config.

| Key            | Type                                  | Rule                                                                                                                                                                        |
| -------------- | ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `withHeadings` | boolean                               | 2.3: first row is a header row (`<thead>`, `<th scope="col">`)                                                                                                              |
| `stretched`    | boolean                               | 2.3                                                                                                                                                                         |
| `content`      | `string[][]` (inline HTML)            | max 500 rows (`TABLE_LIMITS.rows`) x 100 columns; with `merges` a full rectangle, covered cells `''`                                                                        |
| `headerColumn` | `true`                                | first column is a header column (`<th scope="row">`); only stored when true                                                                                                 |
| `align`        | `('left'\|'center'\|'right'\|null)[]` | per column, cut to the column count, trailing nulls removed, omitted when empty                                                                                             |
| `merges`       | `{ row, col, rowspan, colspan }[]`    | max 1000; integers, at least two cells, inside the grid, never from the header row into the body, no overlap (first wins), sorted; invalid ones are dropped, never repaired |
| `caption`      | inline HTML                           | input cut to 4000 characters, omitted when blank                                                                                                                            |

- Compatibility: the policy writes the new keys only when they differ from the default, so stored tables from before 2.4 keep their exact shape and renderer output (`tests/table-v2.test.mjs`, `tests/render.test.mjs`). No migration. A renderer that ignores the new keys shows a full grid: text in the anchor cell, covered cells empty (the policy empties them; the editor joins the merged texts with `<br>` into the anchor).
- Renderers (`render/tree.mjs`, so HTML, React and Vue): `<caption>` first, `colspan`/`rowspan` on anchors (covered cells left out), alignment as class `mex-align-<value>` (no inline style), no scroll wrapper. Text: tab-separated rows, caption as first line. Markdown (GFM): alignment row (`:---`, `:---:`, `---:`), caption as a paragraph before the table; merged cells cannot be expressed: the text stays in the first cell, covered cells are empty; the header column is not expressible.
- Conversion (`convert/html.mjs`): first row header when in `<thead>` or all `<th>`; header column when every body row starts with `<th>` and the body has `<td>`; `colspan`/`rowspan` become merges (bounded; a rowspan ends with its row group); `text-align`/`align` on the cell or shared by all its paragraphs (Word, Google Docs) becomes the column alignment when all non-empty body cells of the column agree; `<caption>`. Markdown: GFM alignment row.
- Quality: `table-no-header` passes with a header row or a header column; `table-empty-header` (warning, `params: { count }`) counts empty header cells (not covered cells, not the corner cell when both header kinds are on, not tables of one row/column). Diff: `merges` (`A1:B2, ...`) and `align` (`left, -, center`) are single values; the caption is text. Find and replace: cells, then `caption`.
- Live guard (`ydoc-guard.mjs` → `isTableDataShapeValid`): refuses wrong types and bounds of `content`, `headerColumn`, `align`, `merges` (exactly the four integer keys, row < 500, col < 100, spans 1..limit) and `caption` (string, max 4000) with `INVALID_BLOCK`. Merges that overlap or leave the grid (two people changing the table at once) are accepted and dropped by the policy when rendered or saved.
- Editor tool (`admin/src/editor/tools/table.js`, replaces `@editorjs/table`): a real `<table>`; one contenteditable per anchor cell (`role="textbox"`, label "Row r, column c"); toolbar (`role="toolbar"`, roving tabindex, Alt+F10 from a cell, arrows/Home/End, Escape or Tab back): header row, header column, align column left/center/right (toggle), merge selected cells (Shift+click or drag selects a rectangle, grown to whole merges), merge right, merge down, split, add row above/below, delete row, add column left/right, delete column. Block settings: header row, header column, full width. Keys: Tab/Shift+Tab next/previous cell (Tab in the last cell adds a row), Enter cell below (adds a row at the end), Shift+Enter line break, arrows at the cell edge move to the neighbour (Up from the first row to the previous block, Down from the last row to the caption). Paste in a cell: tab-separated text fills the grid from the cell (rows/columns added up to the limits, covered cells skipped), other content is inserted as inline text (`htmlToInline` + DOMPurify); never handled by `paste.js` (`.mex-table-tool`) or Editor.js. A whole `<table>` pasted outside a cell becomes a table block through `htmlToBlocks` + the policy (`pasteConfig` tags). The wide table scrolls in `.mex-table-tool__scroll`.
- Collaboration: the Yjs mapping is generic (cells are Y.Text, merges Y.Maps). `apply-remote.js` now clears data keys a collaborator removed (`blocks.update` merges data) and restores the caret in the input it was in (any cell or caption), not only the first one.

## Custom block SDK (2.3, `shared/blocks/`)

- Definition (`defineBlock` from `magic-editor-x/blocks`, frozen, validated, throws `BlockDefinitionError` with `code` `INVALID_DEFINITION` \| `RESERVED_NAME` \| `NAME_TAKEN` \| `REGISTRY_SEALED`): `{ name (/^[A-Za-z][A-Za-z0-9_-]{1,49}$/, not in RESERVED_BLOCK_NAMES ignoring case), version (1-1000000, default 1), title?, description?, schema, sanitize?, text?, markdown?, render?, presets? ('article'|'basic'|'minimal') }`; unknown keys are rejected. `RESERVED_BLOCK_NAMES` covers `BLOCK_POLICIES`, `BUILTIN_BLOCKS`, the custom-block `RESERVED_NAMES` and the media names (test enforced).
- Schema: `{ key: field }` (1-50 keys `/^[A-Za-z][A-Za-z0-9_]{0,63}$/`), field types `text` (`max` default 1000, cap 100000), `inline` (inline policy; input cut to `max` default 10000), `url` (`sanitizeUrl`, `schemes` subset of http/https/mailto/tel, default http+https, `relative` default true; input cut to 2048), `enum` (`values` 1-100, `default` = first), `number` (`min`, `max`, `integer`, `default`; no default = key omitted when invalid), `boolean`, `array` (`items`, `max` default 50, cap 500; items of another JS type dropped), `object` (`fields`); optional `label`; nesting depth 4; budget 20000 values per block (`BLOCK_LIMITS`). Cleaning (`compileBlock(def).clean(data, inline)`) never throws, is idempotent, emits the declared keys in declaration order, drops everything else. `sanitize(cleanData, { sanitizeUrl })` runs after it and its result is cleaned again; a throwing hook is ignored. `blockJsonSchema(def)` is the JSON Schema of the cleaned shape (`additionalProperties: false`).
- Registries: `shared/blocks/active.mjs` holds one registry per bundle (server bundle, admin bundle). `registeredBlockOf(block, explicit?)` (sanitize-policy) returns the definition for non-built-in types; built-in blocks (and media legacy data) always keep their policy. Used by `sanitizeEditorData`, `prepareBlocks` (renderers), `searchableFields` (find and replace, AI field segments), `leafKind` (diff), `inlineStrings`/`extractLinks` (quality: inline fields, URL fields as external links), `blockLinkKinds` (URL fields count as external links), `computeStats` (text and inline fields only) and `resolveFieldPreset` (definitions join the named presets in their `presets`; `full` includes them; `allowedBlocks` may list them).
- Server: service `blocks` (`register(def)`, `list()`, `get(name)`, `summaries()`, `isRegisteredName(name)`, `verify()`). The host calls `strapi.plugin('magic-editor-x').service('blocks').register(def)` in its `register()`; plugin bootstrap runs `verify()`: a Settings custom block with the same name (ignoring case) throws `NAME_TAKEN` (Strapi does not start), then the registry is sealed (`REGISTRY_SEALED` afterwards). `destroy` clears it. Settings create/update answers 400 `fieldErrors.name: ['A block with this name is defined in code']`; import skips such names with `reason: 'exists'`. `GET /config` adds `data.codeBlocks: [{ name, version, title, presets, fields: [{ key, type }] }]`. The Document Service middleware, the collaboration guard (preset rule; the guard itself accepts any block type name), `?mex=`, GraphQL `…Rendered`/`…Resolved` use the registry without further wiring.
- Removed definitions: stored blocks stay and fall back to the generic policy (every string is inline HTML, so markup in former text fields is cleaned, `&` becomes `&amp;`), neutral rendering.
- Admin: `app.registerPlugin({ apis: { registerBlock, createReactTool } })`. `registerBlock({ definition, tool, title?, icon?, i18n?, inlineToolbar?, shortcut? })` registers the definition in the admin registry (so `prepareEditorValue` and everything above clean with it) and the tool; `buildTools` adds `{ class, toolbox: { title (localised), icon (sanitizeSvg) }, inlineToolbar?, shortcut?, config: { ...shared, t, locale, definition, translate(key, fallback), clean(data) } }` and `applyPreset` handles it like any block. A tool without `static sanitize` gets rules derived from the schema (`sanitizeRulesFor`: inline fields keep the inline tags with `LINK_SANITIZE`, other strings `true`). `createReactTool(Component, { className? })` mounts with `react-dom/client` `createRoot`, props `{ data, onChange, readOnly, translate, definition }`, unmounts on `destroy`/`removed`. `EditorField` passes `locale` (admin locale) to `buildTools`. Code tools may use the stable theme classes `mex-tool__field`, `mex-tool__label`, `mex-tool__input`, `mex-tool__select`, `mex-tool__editable` (styles.js; keep them). Settings > Custom blocks shows `CodeBlocksSection` (read-only, "Defined in code"; warnings when only the server or only the admin knows a block; `mergeCodeBlocks`).
- Renderers: option `blocks: [definition]` (compiled once per array; replaces the bundle registry for that call). Order: `overrides` / React `components` / Vue slots, then built-in renderers, then the definition: `render(publicBlock, helpers)` nodes validated by `cleanOverrideNodes`; `[]` renders nothing; null/undefined/throw = default (`<div class="mex-block mex-<type>" data-mex-block>` with `<div class="mex-field" data-mex-field>` per top-level text/enum/number/boolean (text), inline (inline nodes), url (`<a href>`) field); a string only with `rawHtml: 'allow'` + `sanitizeRaw` (also in `renderHtml`). `text(data, { text })` / `markdown(data, { escape, inline, text })` return strings, default = text and inline fields (one per line / escaped paragraphs).
- Package: `exports['./blocks']` (`dist/blocks/index.{mjs,js}`, types `dist/blocks/index.d.ts` from `types/blocks.d.ts`), built by `scripts/build-server-bundle.mjs`, checked by `verify:runtime` (no Node built-ins, framework or zod imports; a definition from the blocks bundle renders through the render bundle).

## Math and footnotes (2.4)

- Library: Temml 0.14 (`temml`, MIT, MathML Core output only, no dependencies, no `eval`/`new Function`; chosen over KaTeX 0.19: about 50 KB instead of 77 KB gzip, no HTML/CSS output to sanitise, no `commander` dependency, same parser lineage). Settings (`shared/math/index.mjs` `MATH_SETTINGS`): `trust: false` (no `\class`, `\id`, `\style`, `\data`, `\includegraphics`; Temml has no `\href`/`\url`), `throwOnError: true`, `strict: false`, `annotate: true` (TeX annotation), `maxSize: [20, 200]` (em, pt), `maxExpand: 500`, fresh `macros` per call.
- Stored data: block `math` `{ tex (plain text, max `MAX_MATH_TEX` 10000), display (boolean, default true; false = text style), _mex: 1 }` (built-in marker: `MARKED_BLOCKS.math` keys `tex`, `display`, anchor `tex` string; a Settings custom block named `math` from before 2.4 keeps its data, policy and tool; new Settings blocks cannot take the name (`LEGACY_BUILT_IN_NAMES`, admin `LEGACY_NAMES`); `RESERVED_BLOCK_NAMES` of the block SDK contains `math`). Inline math `<span data-mex-math="true">TeX</span>` (text only, max `MAX_INLINE_TEX` 2000; zero-width spaces dropped). Footnote marker `<sup data-mex-footnote="<id>" data-mex-note="<note inline HTML>">placeholder</sup>` (`FOOTNOTE_ID` `/^[A-Za-z0-9_-]{1,64}$/`, note input max `MAX_FOOTNOTE_NOTE` 4000; the note follows the inline policy without footnotes and without entry-reference attributes; the marker text is a placeholder, numbers are computed). Only sources are stored, never rendered markup.
- Footnote design (decided): the note lives in its marker. Collaboration merges two people adding footnotes like any text edit (random 12-character ids `fn…`, `newFootnoteId`), undo, copy/paste between fields, synced blocks and templates move note and reference together, a deleted marker takes its note with it (no orphan notes by construction), numbers follow the reading order of the rendered output. Every marker is its own footnote; a repeated id (a copied marker) gets anchor `<id>-2`. A separate `footnotes` block was rejected: copy/paste and synced blocks would split reference and note, deletions would leave orphans, and two users appending notes would need extra merge rules.
- Canonical form: `render/inline.mjs` parses math and markers specially (`isMathNode`, `isFootnoteNode`, `node.note`) and `canonicalInlineExtras(html, { footnotes })` writes the stored form; the server (`utils/sanitizer.js`, after sanitize-html) and the admin (`editor/sanitize.js`, after DOMPurify with `ADD_URI_SAFE_ATTR` for the three attributes) both call it. Presets: inline tools `inlineMath` (`span`) and `footnote` (`sup`) in `INLINE_TOOL_TAGS`; `full` and `article` include the `math` block and both tools, `basic`/`minimal` do not (math is unwrapped to its TeX, footnote markers are removed with their notes; a math block answers `BLOCK_NOT_ALLOWED`). Links inside notes count for `linkTargets` (`blockLinkKinds`), the link check (`extractLinks`) and quality; `fixPresetViolations` unwraps them through `mapFootnoteNotes`.
- Renderers (`render/math-notes.mjs`, `render/mathml.mjs`): option `math(tex, { display }) -> MathML string | nodes`; the result is parsed through a MathML Core allow-list (`MATHML_TAGS`: math, semantics, annotation (only `application/x-tex`), mrow, mi, mn, mo, ms, mtext, mspace, msub, msup, msubsup, munder, mover, munderover, mfrac, msqrt, mroot, mstyle, merror, mpadded, mphantom, mtable, mtr, mtd, mlabeledtr, mmultiscripts, mprescripts, none, menclose; per-element attributes with values `/^[A-Za-z0-9 .%#+-]{0,100}$/`, colours only as `mathcolor`/`mathbackground` (a `style` colour is converted), classes only `tml-*`; no href, style, id, on*, xmlns, annotation-xml, HTML or SVG). Output: inline `<span class="mex-math" data-mex-math="inline"><math>…</math></span>`, block `<div class="mex-math mex-math-display" data-mex-math="display">` (`display: false`: `class="mex-math" data-mex-math="inline"` on the div). Without the option, or when it throws or returns nothing usable: the escaped TeX between `\(` `\)` / `\[` `\]` in the same element (client-side KaTeX auto-render or Temml `renderMathInElement` pick it up). Helper export `magic-editor-x/math` (`dist/math`, Temml external, checked by `verify:runtime`): `renderMath(tex, { display }) -> string | null`, `checkMath(tex, { display }) -> { ok } | { ok: false, message }`, `MATH_SETTINGS`.
- Footnotes in HTML/React/Vue: marker `<sup class="mex-footnote-ref"><a href="#<p>fn-<id>" id="<p>fnref-<id>" aria-describedby="<p>footnotes-label">n</a></sup>`; after the content `<section class="mex-footnotes" aria-labelledby="<p>footnotes-label"><h2 id="<p>footnotes-label" class="mex-footnotes-label">label</h2><ol class="mex-footnotes-list"><li id="<p>fn-<id>" class="mex-footnote">note <a href="#<p>fnref-<id>" class="mex-footnote-back" aria-label="Back to reference n">↩</a></li>…`. Option `footnotes: { label (default 'Footnotes'), backLabel (default 'Back to reference {n}'), prefix (default 'mex-', `/^[A-Za-z][A-Za-z0-9_-]{0,40}$/`) }`. Text: `[n]` and a `label` paragraph with `[n] note`; Markdown: GFM `[^n]` and `[^n]: note` (labels `<prefix>n` only when `footnotes.prefix` is set). Math in text output is the TeX source; in Markdown `$…$` / `$$…$$` with fences longer than any `$` run, blank lines removed and `<` followed by a letter, `/`, `!` or `?` given a space (cannot open HTML or an autolink in pipelines without math support). Heading text, toc entries, stats and diff ignore marker text.
- Content API (`?mex=html|text|markdown`) and GraphQL `…Rendered` render MathML with `renderMath`; HTML output gets a per-value footnote prefix `mex-<sha256(locale|first block id) 8 hex>-`, so several fields or entries in one response do not repeat ids.
- Quality (`lintDocument` option `checkMath`): `math-invalid` (warning, math blocks path `tex`, inline math path of the field) when the checker says the TeX does not parse; `footnote-empty` (warning). The admin loads the checker with Temml on demand.
- Admin: block tool `tools/math.js` (`markedTool`; TeX textarea, `enableLineBreaks`, style select, live preview, parser errors with `aria-invalid`), inline tool `tools/inline-math.js` (`InlineMathTool`; Ctrl/Cmd+Shift+E wraps a selection or inserts a formula at the caret; polite preview popover next to the holder; Escape, or ArrowRight at the end, leaves the formula), inline tool `tools/footnote.js` (`FootnoteTool`; Ctrl/Cmd+Alt+F, not with AltGraph; markers atomic with DOM-only `contenteditable="false"`, numbered by the CSS counter `mex-footnote`; Backspace/Delete next to a marker remove it; click opens the note), `FootnoteDialog` (note editor: bold, italic, link as the preset allows; Enter = line break, Ctrl/Cmd+Enter saves and never reaches the Content Manager save shortcut), `FootnotesPanel` (list under the editor: go to, edit, remove with ConfirmDialog). Tool keys `inlineMath`/`footnote` become `inlineMath$mex`/`footnote$mex` when a Settings or code block owns the name. Editor.js span/sup rules come from `tools/sanitize-config.js` `SPAN_SANITIZE`/`SUP_SANITIZE`. Temml is loaded with `import()` (`editor/math-view.js` `loadMath`) into its own chunk; MathML reaches the DOM only through the allow-list and `createElementNS`. The paste handler leaves an Editor.js block clipboard (`application/x-editor-js`) to Editor.js when every block's tool exists and is allowed in the field (`editorClipboardFits`); the HTML converter keeps math and footnotes in their canonical form.
- No new routes, permissions, config keys or tables.

## Field presets (`shared/presets.mjs`)

- Options: `preset` (`full` default \| `article` \| `basic` \| `minimal`; `full` and `article` include `gallery`, `video`, `audio` and `synced`, `basic` and `minimal` do not), `allowedBlocks` (comma list, replaces the preset's blocks), `headingLevels` (`2-4`, `2,3`), `maxBlocks`, `maxCharacters` (positive integers; 0/empty = none), `requireAlt`, `linkTargets` (`all` \| `internal` \| `external` \| `none`), `disableAi`, `disableGrammar`, `disableCollaboration`, `publishGuard`. Invalid values fall back to the defaults.
- `resolveFieldPreset(options)` -> `{ name, blocks|null, inline|null, headingLevels, maxBlocks, maxCharacters, requireAlt, linkTargets, ai, grammar, collaboration, publishGuard, restricted }`; `paragraph` is always allowed; no `header` in the list means no heading levels. `toc` is in `full` and `article`, not in `basic`/`minimal`.
- Save: `checkPreset(clean, preset)` -> violations `{ code, blockId, index, params }` with codes `BLOCK_NOT_ALLOWED`, `HEADING_LEVEL`, `LINK_NOT_ALLOWED` (internal = `<a data-mex-uid>`; `linkTool`/`button`/`personality` links are external), `ALT_REQUIRED` (also a gallery with an image without alt that is not decorative), `TOO_MANY_BLOCKS`, `TOO_MANY_CHARACTERS` (characters as `computeStats`). Any violation -> `ValidationError` `details: { code: 'PRESET_VIOLATION', violations: [{ field, ... }], errors }` (max 50, no content). Inline tags of tools the preset leaves out are unwrapped (`allowedInlineTags`).
- Live: `services/collaboration.js` passes `checkBlockStructure` as `checkBlock` to `applyCheckedUpdate`; it runs only for blocks whose entry was added or whose `type` or `data.level` changed in the update (`touchedBy(...).structural`), so blocks that existed before a preset was tightened stay editable. Refusal = `INVALID_UPDATE`.
- AI: the AI route requires `target: { uid, field }`; unknown field 404, `disableAi` 403. Grammar (`POST /grammar/check`, independent of `disableAi`): unknown field 404, `disableGrammar` 403 before anything is sent; the editor hides "Check grammar" for such fields. Sessions: `disableCollaboration` 403.
- Admin: `buildTools({ preset })` -> `applyPreset` hides blocks that are not allowed from the toolbox and paste (subclass with `pasteConfig` false, config `toolbox: false`), limits header levels and inline tools, passes `linkTargets` to the hyperlink tool and `requireAlt` to the image tools. The inline tool `mention` (Ctrl/Cmd+Shift+2) is offered right after `hyperlink` when the field allows the hyperlink tool and `linkTargets` is `all` or `internal`; it is not a preset inline name of its own. `fixPresetViolations(data, preset)` is the "Fix automatically" action.

Details:

- Ids in paths are `documentId`s (`/^[a-z0-9]{1,64}$/`). Field targets: `uid` `api::x.y` or `plugin::x.y`, `field` a dotted path (`body`, `sections.0.body`) that must resolve to a Magic Editor X attribute, `locale` a locale code (required in effect for localised types; defaults to the default locale).
- Validation errors: `ValidationError` 400 with `details: { formErrors, fieldErrors }`, keys are dotted paths (`ai.apiKey`, `fields.2.name`).
- Access denied or missing document: 404. Viewer trying to write a version: 403.

## Collaboration protocol (3)

Rooms, versions and comments are keyed by the field identity (see Field identity (2.4)): the path for top-level fields and fields in single components, `<path without indices>#<fieldKey>` for fields inside a repeatable component or a dynamic zone. A positional path (`sections.0.body`) names another entry after entries are removed, added or moved, so it is never used as a key. The admin starts the room of such a field once its key is saved with the entry; before that the field is edited locally and shows a hint (`admin/src/editor/field-path.mjs`, `tests/field-path.test.mjs`).

1. The admin calls `POST /collaboration/session`. The server checks the shared per-admin session limit (`magic_editor_x_counters`, `collaboration.rateLimit.sessionsPerMinute`, 429), access (`services/access.js` `checkField`), seeds the room once from the stored draft (or `initialValue` when nothing is stored and the caller can edit; lease `seed:<room>`; every seed gets a new `meta.epoch`) and returns an HMAC-signed token (`admin.auth.secret`, HKDF purpose `magic-editor-x:collaboration-token`) with `{ room, target, userId, name, color, canEdit, protocol: 3, nonce, exp }`. Response `{ data: { token, path, canEdit, seeded, protocol, expiresAt } }`.
2. The browser opens Socket.IO on `path` with `transports: ['websocket']` and `auth: { token, protocol: 3 }`. A handshake middleware checks the origin (upgrade), protocol, signature, expiry, consumes the nonce once (`tok:<nonce>` lock) and the per-admin caps (`maxConnectionsPerAdmin`, `maxRoomsPerAdmin`, counted from fresh presence rows across processes). Refusals arrive as `connect_error` with `data.code`: `UPGRADE_REQUIRED`, `INVALID_TOKEN`, `TOO_MANY_CONNECTIONS`, `UNAVAILABLE`. Every reconnect requests a new token.
3. Events:

| Direction        | Event         | Payload                                                                                                                                                                                              |
| ---------------- | ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| server -> client | `mx:welcome`  | `{ canEdit, presenceId, color, name, epoch, protocol }`                                                                                                                                              |
| server -> client | `mx:sync`     | `{ update, stateVector, epoch }` (full room state, or the missing part after `mx:resync`)                                                                                                            |
| client -> server | `mx:update`   | Yjs update bytes, ack `{ ok: true, id }` (`id` 0 when nothing new) or `{ ok: false, code: 'READ_ONLY' \| 'INVALID_UPDATE' \| 'RETRY' \| 'RATE_LIMITED' \| 'ROOM_FULL' \| 'STORE_FAILED' }`           |
| server -> client | `mx:update`   | Yjs update bytes from others                                                                                                                                                                         |
| client -> server | `mx:resync`   | client state vector (every 20 s, after reconnects and wake-ups; at most one per second)                                                                                                              |
| client -> server | `mx:cursor`   | `{ blockId, anchor, focus, idle }` (character offsets in the block's text; at most one per 50 ms)                                                                                                    |
| server -> client | `mx:presence` | `[{ id, name, color, canEdit, idle, cursor: { blockId, anchor, focus } \| null }]`; `color` is a Design System colour family (`primary`, `danger`, `success`, `warning`, `secondary`, `alternative`) |
| server -> client | `mx:role`     | `{ canEdit }` after a permission change                                                                                                                                                              |
| server -> client | `mx:error`    | `{ code: 'ACCESS_REVOKED' \| 'ROOM_RESET' \| 'INVALID_UPDATE' }` (the socket is closed after it)                                                                                                     |

4. Every process keeps an in-memory Y.Doc per room with local sockets. An update is checked by `shared/ydoc-guard.mjs` `applyCheckedUpdate` (allowed structures, dependencies present, touched blocks valid, field preset structure rules), appended to `magic_editor_x_collab_updates`, then acknowledged and relayed. `RETRY` means missing dependencies (nothing stored). Five refused updates close the socket. Per-socket budgets: `rateLimit.updatesPer10s`, `rateLimit.bytesPer10s`. Other processes poll rows with `id` above their watermark every `collaboration.pollIntervalMs` (rows of the last 5 seconds are re-read to tolerate commit order), apply them to their room and relay them; `compact` rows are not relayed; a `seed` row with a new epoch ends the room's sockets with `ROOM_RESET`. Rooms with 200+ rows are compacted under a lease. Rooms have a generation row `gen:<room>` in `magic_editor_x_locks` (owner = epoch). Appends run in a transaction that reads it with a shared lock and fail with `STALE_GENERATION` (answered `RETRY`) when the room moved on. Generation compaction (`collaboration.compaction`): when a room is idle for `idleSeconds`, at least `minBytes` and `ratio` times larger than a fresh encoding, one process (lease `compact:<room>`) writes a new `seed` row with a new epoch and deletes the old rows in one transaction (row lock on the generation row; aborted when rows were written meanwhile); every process switches its room and sends `mx:sync` with the new epoch; updates of client ids from older generations get `RETRY`. `applyCheckedUpdate` stores every update that advances the state vector.
5. Automatic versions: lock `snap:<room>:t<bucket>` when a `snapshotIntervalMinutes` bucket with changes ends (the first tick after it) and `snap:<room>:end<lastId>` when the last local socket leaves; the lease is released when creating the version fails. Maintenance (under the `maintenance` lease) prunes presence, locks and counters and deletes rooms idle for `roomTtlMinutes` without presence after a final version (`end<lastId>`, skipped when equal to the saved draft).
6. Permissions: a lifecycle subscriber on `admin::permission`, `admin::role` and `admin::user` sets the lock row `signal:permissions` to a new value; every process compares it every second and re-checks all sockets (`mx:role` or `ACCESS_REVOKED`). Full re-check every `collaboration.revalidateSeconds`.
7. Client (`admin/src/editor/collab-client.js`): one update in flight, later edits merged; unacknowledged edits kept across disconnects; backoff 0.5 s to 15 s with jitter and a manual reconnect after handshake refusals; `online`, `offline`, `visibilitychange` and `pagehide` handled; idle after 60 s or when hidden; a new epoch or `INVALID_UPDATE` starts over with fresh documents (unsent edits are rebased onto the new room after a new epoch, with the acknowledged server state as base and the editor view as the diff base). Undo/redo use the replica's Y.UndoManager (own changes only).

Tables (created in `services/store.js`, not content types):

- `magic_editor_x_collab_updates (id, room, kind 'seed'|'update'|'compact', data base64, size, created_at)`
- `magic_editor_x_collab_presence (id, room, user_id, name, color, can_edit, cursor, updated_at)`
- `magic_editor_x_locks (key, owner, expires_at)` (leases, one-time keys, `signal:*` rows)
- `magic_editor_x_counters (key, count, expires_at)` (fixed-window counters: `session:<adminId>`, `ai:<adminId>`, `links:<adminId>`, `links:schedule`, `comments:<adminId>`, `grammar:<adminId>`)
- `magic_editor_x_link_fields (key sha256(uid|documentId|locale or -|field|version), uid, document_id, locale, field, version 'draft'|'published', links JSON [{ h: url hash, b: blockId }] max 200, run_id, scanned_at)`
- `magic_editor_x_link_urls (hash sha256(url), url, status, code, checked_at, run_id)`
- `magic_editor_x_audit` (2.4, see Audit trail)

Room key: `<uid>|<documentId>|<locale or ->|<field identity>`, the same as `roomId` of versions (`targetOfRoom` parses it back).

## Field identity (2.4)

Editor fields inside a repeatable component or a dynamic zone have positional paths (`sections.0.body`, `zone.1.body`, `groups.0.items.2.body`). 2.3.1 turned off their live rooms, versions and comments because all three were keyed by that path. 2.4 keys them by an identity stored in the value.

- Value: a top-level `fieldKey` next to `time`, `blocks`, `version`, only on non-null values of positional fields: 16-32 characters `[A-Za-z0-9_-]` (`FIELD_KEY_PATTERN`; the plugin generates 22 from 16 random bytes, `createFieldKey`). `normalizeEditorData` keeps a valid key and drops an invalid one, `sanitizeEditorData` keeps it, renderers ignore it, the JSON Schema (`fieldKey`, pattern) and `MagicEditorXData.fieldKey?` describe it. Content API and GraphQL output keep it (additive key). Versions never store it (`history.create` removes it), templates never store it. Yjs rooms do not carry it: the room key is the identity, `meta` is unchanged.
- Why not component ids: Strapi 5.61 publishes and discards drafts by creating new component rows without ids (`@strapi/core` document-service `entries.js` `publishEntry`/`discardDraftEntry`, `components.js` `createComponent` omits `id`), new entries have no id until saved, and the Content Manager form uses temporary keys. The key lives in the JSON value, which publish, discard draft, the Content Manager "Fill in from another locale" and document duplication copy as is. Strapi 5.61 has no duplicate action for repeatable entries; duplicates in one write (API clients, imports) get a new key.
- Assignment (Document Service middleware in `register.js`, after cleaning and the preset check, on `create` and `update`): `assignFieldKeys` gives every non-null positional value without a valid key a new key; a key already used earlier in the same write (document order) is replaced; a non-positional value loses any key; `null` stays `null` (required checks unchanged). On `update`, a component entry sent with its `id` but without a key keeps the key the stored draft has for that row (`<base path>|<component id>`, one draft read per base path, only when such values exist), so API clients that drop unknown keys do not change identities. The admin generates a key when the user edits a keyless positional value (`EditorField` `emit`) and reads the stored key back from the value after the Content Manager reloads the form.
- Identity (`shared/field-identity.mjs`): `fieldIdentity(path, key)` = the path for stable fields, `<base path>#<key>` for positional fields (`basePathOf('zone.1.items.0.body')` = `zone.items.body`; a dynamic zone with several component types shares one namespace per attribute name). `parseFieldIdentity(name)` -> `{ field, fieldKey, legacy }` (`legacy`: a positional path stored before 2.4). Stored as `fieldName` of versions and comments, `roomId`/room key, and `field` of `magic_editor_x_link_fields` (link scanner; values without a key keep their positional path there and are never served).
- Server resolution (`services/access.js` `checkField({ ..., field, fieldKey?, allowUnsavedKey? })`, the one place everything uses): returns `fieldName` (identity or null), `fieldKey`, `positional`, `basePath`, `unsaved`, `entries` (stored entries of the base path: path, key, block ids, component id). `resolveEditorField` accepts paths with or without indices and rejects an index after a single component. Stable field: `fieldName` = path; a `fieldKey` is 404. Positional field with `fieldKey`: the stored draft of the document and locale must have a value with that key at the same attribute (any index), else 404; `allowUnsavedKey` (live sessions only) accepts an unsaved key when the caller can update the document (`unsaved: true`). Positional field without `fieldKey`: the key of the stored value at the path's index; none -> `fieldName: null`. Reads then serve only rows proven to be that entry's; writes answer 409 `FIELD_KEY_REQUIRED`.
- Unsaved keys and live sessions: an editor (update permission) may open a room for a key that is not saved yet; the room is seeded from `initialValue`, keyed by the 128-bit key nobody else knows until the entry is saved, and revalidation keeps the same rule (a reader is 404 / `ACCESS_REVOKED`). The admin itself starts rooms only for saved keys, so other editors can join. Rooms of positional paths made before 2.4 are abandoned; their final version is written under the positional path as before and then mapped like any legacy row.
- Rows stored before 2.4 under positional paths (versions, comments): mapped lazily on `GET /history` and `GET /comments` of any entry of that base path (no bootstrap job: before an entry has a key there is nothing to map to, and writing keys into content during a migration would change entries behind the editors' backs). A row belongs to the one current entry whose blocks contain the row's block ids (versions: any block id of the content; comments: the thread's `blockId`; Editor.js ids are random 10-character strings) - `ownerOfBlocks`; no match or several matches = unmapped. Mapped rows of keyed entries are moved once (`fieldName`, versions also `roomId`; `updateMany` guarded by the old name, so concurrent mappings write the same result once; replies move with their thread). Rows mapped to a keyless entry are served for it (not moved). Unmapped rows stay as they are: listed read-only under `meta.positionalVersions` / `meta.positionalThreads` (with `positional: true`, versions `restorable: false`), viewable (`GET /history/:id`), no rename, restore, reply, edit, resolve, reopen or delete (409 `POSITIONAL_READ_ONLY`). Nothing is deleted; rows of deleted entries stay stored and are no longer served. Bounds: 2000 legacy version candidates (content loaded in batches of 50), 4000 comment rows per call. Version numbers of mapped rows are kept (an entry can show two sequences); `history.maxSnapshotsPerField` applies to the identity after mapping.
- Limits: a value emptied and saved becomes `null` and loses its key (the next edit gets a new one; the old rows are no longer served). An entry whose published version predates 2.4 loses keys added to the draft when the draft is discarded. Content API writes that send positional values without key and without component `id` get new keys on every write.

## Collaboration document model (schema 3, `shared/ydoc.mjs`)

```text
Y.Doc
├─ meta   Y.Map   { schema: 3, time: number, version: string, epoch: string }
├─ order  Y.Array<string>                 block ids in document order (duplicates from concurrent moves keep the first position)
└─ blocks Y.Map<blockId, Y.Map>           entries are never deleted; `order` decides visibility
     └─ { type: string,
          tunes: Y.Map  (structured like data),
          data:  Y.Map  JSON object -> Y.Map, array -> Y.Array, string -> Y.Text, number/boolean/null -> plain value }
```

- Inline formatting stays HTML inside the Y.Text (the Editor.js string), so the stored JSON and the tool contracts are unchanged. Range anchors (`Y.RelativePosition`) on these texts are possible; they point into the HTML source. Formatting as Yjs attributes is not used (the guard refuses `ContentFormat`).
- Writing: `applyLocalChanges(doc, base, local, origin)` applies the change `base -> local` structurally (text diff on Y.Text, LCS alignment for arrays with in-place merges of changed items, key-wise for maps). `applyEditorDataToDoc` is the two-way form. `createSeedUpdate(data, epoch)`, `epochOf(doc)`, `docToEditorData(doc)`, `createDocReader(doc)` (incremental), `readShared`/`toShared` (depth-bounded).
- `shared/collab-replica.mjs`: `doc` (shared state) plus `shadow` (what the editor shows). Local edits are diffed against the shadow and applied to `doc` as a Yjs update (origin `LOCAL_ORIGIN`), so Yjs merges them by item identity. `snapshot()` / `markShown(catchUp, shown)` / `rebase(from, data)` / `undo()` / `redo()`.
- Schema 2 rooms (2.0) read with the same reader; values are converted to their structured form on the first local change. 1.x states: `legacyStateToEditorData(update)`.

## Version history

Content type `plugin::magic-editor-x.document-snapshot` (table `magic_editor_doc_snapshots`, 1.x columns kept): `roomId`, `contentType`, `entryId`, `entryLocale`, `fieldName`, `version`, `trigger` (`manual` \| `auto` \| `restore` \| `legacy`), `contentHash`, `jsonContent`, `yjsSnapshot` (1.x only), `createdBy`. Inline HTML is re-parsed by `render/inline.mjs` `parseInline` (allow-list from the sanitize policy, entities decoded before URL checks, dangerous containers dropped with content) and turned into nodes by `inlineToNodes`. No dependencies, no Node built-ins, no framework imports (`tests/render-tree.test.mjs` checks the import graph, `verify:runtime` checks the bundles), deterministic.
- Render tree (`render/tree.mjs`): `createTreeBuilder(value, options, mode)` builds nodes `{ type: 'element', tag, attrs, children }` (lower-case names; attrs are strings or `true`), `{ type: 'text', value }` and `{ type: 'raw', html }`, plus internal `{ type: 'block', block, children }` wrappers that the React/Vue components use for `components`/slots; `renderTree` removes the wrappers. Blocks are separated by `\n` text nodes. A raw node only comes from `sanitizeRaw` (opt-in) and is always the only child of its element; adapters drop any other raw node. `renderHtml` = `serializeNodes(builder.nodes)` and is byte-identical to 2.2 (`tests/render.test.mjs`, `tests/render-tree.test.mjs`).
- **Adding a block type** (gallery, video, audio, table of contents, mention, ...): one entry in `RENDERERS` in `render/tree.mjs` returning `el(tag, attrs, children)` nodes (or null to omit) gives HTML, React and Vue output; add the matching entries in `render/text.mjs` and `render/markdown.mjs`, the policy/schema/types for the stored data, and a case in `tests/helpers/xss-corpus.mjs` `xssDocument`, so the React/Vue parity test covers it. Never build HTML strings in a renderer; boolean attributes are `true`, absent ones `undefined`/`false`. New attribute names that React spells differently go into `PROP_NAMES` (and `BOOLEAN_PROPS` for booleans) in `frameworks/react.mjs`.
- Overrides: return nodes (`helpers.h`, `helpers.textNode`, `helpers.inlineNodes`, `helpers.childNodes`), validated by `cleanOverrideNodes` (tag/attribute name patterns, no `on*`/`style`/`srcdoc`, denied tags such as script/style/object/form, URL attributes and `srcset` through `sanitizeUrl`, raw nodes dropped), or a string. A string is HTML: `renderHtml` writes it as it is (2.2 contract, the override escapes); in `renderTree` and the components it is used only with `rawHtml: 'allow'` + `sanitizeRaw`, as the raw child of `<div class="mex-override" data-mex-block="<type>">`, else the default output. `undefined`/`null`/numbers keep the default.
- Media (2.3): gallery `<figure class="mex-gallery mex-gallery-<layout> mex-gallery-cols-<n>" data-mex-layout data-mex-columns><ul class="mex-gallery-items"><li class="mex-gallery-item"><figure class="mex-gallery-figure"><img ...><figcaption>` + optional gallery `<figcaption>`; video `<figure class="mex-video"><video src controls preload="metadata" aria-label=<title> loop? playsinline muted? poster? width? height?><track kind src srclang label default?>…<a href=<file>>title</a></video><figcaption>`; audio the same with `<audio>` (no playsinline/muted/poster). Text: captions/alt (gallery), title + caption or the URL (video/audio); Markdown: one image per line (gallery), `[title](<url>)` + caption (video/audio). The `media(file)` hook runs for every file (gallery images, video/audio files, posters, tracks) and its result is re-validated for that kind.
- Focal point (image blocks, gallery images): default output `data-mex-focal-x`/`data-mex-focal-y` (0..1) on `<img>`, no inline style (CSP friendly: CSS cannot read the attributes into `object-position`, so a frontend that crops with `object-fit: cover` sets `img.style.objectPosition` from them in script, which the CSSOM allows under a strict `style-src`, or uses its framework's style binding). `focalPoint: 'style'` adds `style="object-position:X% Y%"`: the element node gets `style: { 'object-position': 'X% Y%' }` (`nodes.mjs` `safeStyle` allows only this property with percentage values; overrides cannot set it), React gets the `style` prop `{ objectPosition }`, Vue `{ 'object-position' }`. Media Library formats are resized, not cropped, so the same percentages hold for every `srcset` candidate.
- Code blocks: `language-<lang>` on `<code>` for codeFlask (language validated by the policy, `plaintext` fallback). `lineNumbers` adds `mex-code-lines` to `<pre>` and one `<span class="mex-code-line">` per line (newlines kept between spans, numbers from CSS counters, off above `MAX_NUMBERED_LINES` = 20000 lines); `'block'` follows codeFlask `showlinenumbers` like the editor does (on unless stored `false`; plain `code` blocks never). `copyButton` wraps the block in `<div class="mex-code-block" data-mex-code="copy">` with `<button type="button" class="mex-code-copy" data-mex-copy="code" data-mex-copied data-mex-failed>` and `<span class="mex-code-copy-status" role="status" aria-live="polite">`. Defaults off, so 2.2 output is unchanged. Markdown and text keep code as fenced (with language) or plain text.
- Table of contents and heading ids (`render/common.mjs` `annotateHeadings`, `shared/toc.mjs`): option `headingIds` (`true` every heading gets `id="mex-h-<blockId>"`, `false` never, default only when the value has a `toc` block). The anchor is the Editor.js block id, so it survives text edits, reordering and locales filled from another locale; invalid ids fall back to `mex-h-<n>` (n-th heading), repeats get `-2`, `-3`. A `toc` renders `<nav class="mex-toc mex-toc-<style>" aria-label="<title or options.toc.label or 'Table of contents'>">` with an optional `<p class="mex-toc-title">` and nested `<ol|ul class="mex-toc-list"><li class="mex-toc-item"><a href="#mex-h-…">text</a>…</li>` (headings of the whole document, toggle content included, within `minLevel..maxLevel`, empty ones skipped; plain text entries when ids are off); nothing when no heading matches. Text: title plus indented `1.`/`-` lines. Markdown: `**title**` and a nested list linking to GitHub-style slugs of the heading text (`#über-uns`, repeats `-1`), because Markdown pipelines (GitHub, markdown-it-anchor, rehype-slug) assign heading ids themselves; the Markdown output contains no HTML.
- Mentions: renderers add `class="mex-mention"` to `<a data-mex-mention>` (HTML, React, Vue; never stored, `storage: true` re-serialisation in resolve-references, find-replace and `resolveHrefs` keeps the markup as stored). Defaults off, so 2.2 output is unchanged. Markdown and text keep code as fenced (with language) or plain text.
- `magic-editor-x/react` (`shared/frameworks/react.mjs`, `dist/react`, types `types/react.d.ts`): `MagicEditorXContent({ value, options, components })` (fragment, no hooks except in the copy block, which renders static markup when `React.useState` is missing as in React Server Components) and `treeToReact(nodes)`. `components[type]` receives `{ block, helpers: { text, url, inline, renderBlocks }, children }`. `createElement` only; `dangerouslySetInnerHTML` only for raw nodes. ## Content API and GraphQL output (2.3)

Opt-in per request; without it responses are unchanged.

- REST: `?mex=html|text|markdown|json` on GET requests of Content API routes whose handler belongs to an `api::` content type (core `find`/`findOne` of collection and single types, and custom GET actions of the same controller). `middlewares/render-output.js` (registered with `strapi.server.use` in bootstrap) walks `ctx.body.data` along the schema (`utils/output-walk.js`: top-level fields, components, dynamic zones, populated relations; flat and `Strapi-Response-Format: v4` responses) and **replaces** every Magic Editor X value: `json` -> the stored document with resolved references (object or `null`), `html`/`text`/`markdown` -> the rendered string (`''` when empty). Raw HTML blocks are left out of rendered strings (renderer default). Admin routes (`route.info.type !== 'content-api'`), plugin routes and non-200 responses are never touched. Any other `mex` value (also repeated) -> 400 `ValidationError` `details: { key: 'mex', source: 'query', param: 'mex' }`, checked before the controller. An unexpected failure answers 500 with Strapi's generic body (never the stored values).
- `mex` is registered in `register.js` with `strapi.contentAPI.addQueryParams({ mex: { schema: z.enum([...]).optional(), matchRoute: GET routes with route.info.apiName } })` (Strapi's documented way to add Content API query params), so it passes with `api.rest.strictParams: true`. Strapi strips registered extra params before the Document Service. Strapi versions without `addQueryParams` accept `mex` only without strict params.
- Resolution (`services/references.js`, pure parts in `shared/resolve-references.mjs`), always with the caller's Content API auth (`ctx.state.auth`, GraphQL `context.state.auth`):
  - a target type is read only when `strapi.auth.verify(auth, { scope: ['<uid>.find'] })` passes (API tokens: full access, read-only, custom per action; users-permissions user or public role; same rule Strapi applies to populated relations); `api::` types only; Media Library files need `plugin::upload.content-api.find`;
  - Document Service `findMany({ filters: { documentId: { $in } }, locale, status })`, one query per type and locale (types without i18n: one per type), media one `db.query('plugin::upload.file')` query by id/documentId, custom-block definitions one query; `status` is `published` unless the REST request has `status=draft` (GraphQL: `draft` when the parent's `publishedAt` is `null`); every row passes `strapi.contentAPI.sanitize.output(row, model, { auth })` before any field is used;
  - bounds: 500 distinct references and 5 s per response (`LIMITS`); references over the limit or after the time budget stay unresolved; logs carry counts only.
- Results: internal link -> `href` from `links.urlPattern` with the sanitised slug (`renderLinkPattern`); unresolved (missing, draft-only, unreadable type, over the limit) -> the `<a>` is removed and only its text stays (no href, no reference attributes). A resolved mention also takes the entry's current title as its text (from the sanitised row: `title`, `name`, `label`, then the first text attribute); an unresolved mention keeps the text stored at insertion time, which is the title the author saw then (authored content, like any link text; it is never refreshed for callers who may not read the entry). Heading ids are on in `html` output whenever the value has a `toc` block. Embedded entry (custom block with `data.entry.documentId` and `data.contentType` `api::`) -> `data.entry = { ...displayFields, id, documentId, title, href }` from the sanitised live row (display fields: the custom block's `displayFields` plus the keys of the stored summary, scalar values only; title: `titleField`, then `title`, `name`, `label`, then the first text attribute), unresolved -> `data.entry = null` (the stored snapshot is dropped); rendered as `<div class="mex-block mex-entry mex-<type>" data-mex-block><a class="mex-entry-link" href>title</a></div>`, `[title](<href>)` or the title, nothing when unresolved. Image with `file.id`/`file.documentId` -> current `url`, `name`, `mime`, `ext`, `hash`, `width`, `height`, `size`, `formats`; `alt` only when the block has none; unresolved -> the stored file as stored. The same applies to every Media Library file slot (`shared/resolve-references.mjs` `mediaSlots`): gallery images and video posters like images, video/audio files and track files without `alt` and `formats`; all need `plugin::upload.content-api.find`. Internal links keep `data-mex-*` attributes in resolved output. Link titles are not added (the link text is authored content).
- GraphQL (`server/src/graphql.js`, registered in `register.js` through `strapi.plugin('graphql').service('extension').use(...)` only when the GraphQL plugin is installed): for every Magic Editor X attribute `x` of an `api::` content type or a component that is in the schema (`typeRegistry.has`), not private, output not disabled by `shadowCRUD(uid).field(x)`, and without an attribute named `xRendered`/`xResolved`: `xRendered(format: MagicEditorXFormat = HTML): String` (`HTML`, `TEXT`, `MARKDOWN`) and `xResolved: JSON`. Same resolution; values requested in one tick of a request are resolved in one batch per publication status. Component fields resolve against published versions and the default locale for links without a locale.
- `services/links.js` `resolveHrefs` is unchanged (server helper without permission checks).

## Authoring: @ mentions, code file names, pasted video and audio (2.4)

- `@` trigger (`admin/src/editor/mention-trigger.js`, pure rules in `mention-trigger-logic.mjs`): wherever the mention inline tool is offered (preset allows `hyperlink`, `linkTargets` `all`/`internal`, fetch client present), typing `@` at the start of a word in a `paragraph`, `header`, `list`, `checklist`, `quote`, `toggle` or `table` block opens entry suggestions at the caret. `findMentionQuery(textBeforeCaret)`: the `@` must be at the start of the block or follow white space or opening punctuation (`a@b`, e-mail addresses, `x.@` never trigger); the query is the text after it (max 50 characters, no leading space, no double space, no line break). The block is found by `.ce-block[data-id]` (`editor.blocks.getById`), so it stays right after collaborators' edits re-render a block. Never in code, raw HTML, inputs, links or chips (`a`), `data-mutation-free` views, read-only mode or during IME composition (`isComposing`, `compositionend` re-evaluates). Types from `/links/types` (cached, shared with the picker); none readable = no popup and the text stays. Each new `@` starts with the first readable type. Search `/links/search` debounced 200 ms; every newer query aborts the pending and the in-flight search (`AbortController` `signal` of the admin fetch client) and marks the listbox `aria-busy`; Enter while a search is pending inserts the first result when it arrives. Keys (window capture listener, runs before Editor.js, Markdown shortcuts and chip keys): ArrowDown/ArrowUp move, Enter or click inserts (Enter without results closes and keeps its normal job), Escape closes and keeps the typed text (that `@` does not reopen until a new `@` is typed), Tab moves to the content type select when there are several types (Tab/Enter/Escape there return to the text). ARIA: focus stays in the editable, which carries `aria-controls` (listbox), `aria-expanded`, `aria-autocomplete="list"`, `aria-activedescendant` and, when it has no role, `role="textbox"` + `aria-multiline` while open (restored on close); polite live region with the result count. The popup (`.mex-mention-popup`, fixed, `zIndices.popover`, follows the caret on scroll and resize) is a sibling of the holder, so it stays inside the fullscreen dialog; the active option is kept visible by scrolling the list only (`scrollIntoView` would scroll the page behind a fixed popup).
- Code block file name: `codeFlask` data gains optional `filename` (`cleanCodeFilename`: tabs/newlines to spaces, C0/C1 controls, DEL, bidi and zero-width marks removed, white space collapsed, trimmed, max 200 code points `MAX_CODE_FILENAME`; omitted when empty, so stored data without it is unchanged). A plain-text label, never interpreted as a path. Schema `data_codeFlask.filename` (string 1-200), `CodeFlaskData.filename?`. The plain `code` block has no file name (its policy drops the key). Renderers, only with a file name: HTML/React/Vue `<figure class="mex-code-figure"><figcaption class="mex-code-filename">name</figcaption>` + the unchanged `<pre>` or copy-button wrapper; text: the name on its own line before the code; Markdown: ` ```js title="name" ` (language always written, `plaintext` when none; `"` and `\` backslash-escaped; a name with a backtick uses a `~~~` fence). Import: `parseFenceInfo(info)` reads `title=`/`filename=` (double quotes to the last quote, single quotes or bare) and the language (first word unless it is an attribute); a file name without a valid language gives `codeFlask` with `plaintext`; HTML `<figure>` with `<figcaption>` and one `<pre>` (the renderers' output) is imported with the caption as file name. Output for blocks without a file name is byte-identical.

## AI extras and grammar check (2.3)

- Rules: nothing is sent unless the owner turned the feature on in Settings (`ai.enabled` + `ai.allowImages` for alt text, `ai.enabled` + `ai.allowFieldActions` for whole-field actions, `languageTool.enabled` for grammar); every AI route answers 403 for fields with `disableAi` (the grammar check is not AI and ignores it; it answers 403 for fields with `disableGrammar`). Results are suggestions: the server never writes content. Logs carry the action and error code only.
- Alt text (`services/ai.js` `altText`, `utils/media-image.js`): the file is loaded with the upload service and checked like the upload plugin's `findOne` (`createPermissionsManager({ action: 'plugin::upload.read', model: 'plugin::upload.file' })`, creator with roles populated); private providers get `signFileUrls`. The largest stored variant (original or `formats.*`) with a long edge up to 1568 px and at most 3.5 MB is sent; local files are read only from `<public>/uploads` (real path inside it), remote URLs only through `fetchBounded` (public hosts, 2 redirects, image MIME types, size cap). The media type comes from the file signature (JPEG, PNG, GIF, WebP; else 415). Anthropic: `{ type: 'image', source: { type: 'base64', media_type, data } }` before the text; OpenAI and compatible: `{ type: 'image_url', image_url: { url: 'data:<mime>;base64,...' } }`. Language from `locale` (`Intl.DisplayNames`, default English). Answer: plain text, controls removed, cut at a word boundary at 150 characters. Counter `ai:<adminId>`.
- Whole-field actions (`shared/ai-fields.mjs`): `collectSegments(data)` lists the inline HTML strings (`searchableFields` of find and replace, html kind) as `{ blockId, path, html }`; only these are sent. Total plain text over `ai.maxInputChars` is 413. `translate` sends chunks of `{ segments: [{ id, html }] }` (chunk text at most `min(maxInputChars, maxOutputTokens * 1.5)`, max 20 chunks, one counter hit per chunk) and expects the same JSON back; the answer must contain every id once (else 502 `BAD_RESPONSE`), each string is sanitised (`sanitizeInlineHtml`) and links whose `href` the original did not contain are unwrapped (`restrictLinks`). The admin checks the ids again, sanitises (DOMPurify), shows a preview, verifies the field still holds the sent strings and replaces with `applySegments` (ids, types, tunes and all other data unchanged; one undo step). `summarize` returns plain text (copy or insert as a paragraph).
- Grammar (`services/grammar.js`): `POST {baseUrl}/v2/check` form-urlencoded `text`, `language` (`languageToolLanguage(locale)`: region kept, `en`->`en-US`, `de`->`de-DE`, `pt`->`pt-PT`, none -> `auto`), `level=picky` when set, `username` + `apiKey` when stored. Plain text per string (`segmentText`: text nodes, `<br>` = newline) joined with blank lines into requests of at most 20,000 characters (max 5 per check, 60,000 in total, 413 above); matches crossing a separator are dropped, the rest mapped back (`locateInJoined`), max 500. Counter `grammar:<adminId>` (`languageTool.requestsPerMinute`). The admin (`GrammarPanel`) highlights with CSS Custom Highlight `mex-grammar` and applies a replacement with `replaceInSegment` only when the range lies inside one text node and still holds the flagged text.
- Admin helper for other image tools (`admin/src/editor/ai-alt-text.js`): `createAltTextSuggester({ post, getTarget, getLocale })` -> `suggest(fileId, { signal })`, `createAltSuggestion({ t, getFileId, suggest, onUse, readOnly })` -> `{ element, refresh, destroy }`, `mediaFileId(file)`, `altTextErrorText(t, info)`. `buildTools` passes `ctx.suggestAltText` (only when allowed) as `config.suggestAltText` of the image tool.

They are offered only with `plugin::upload.read` (`config.permissions.mediaLibrary`, tool config `canBrowse`); without it they are hidden from the toolbox and existing blocks explain why no files can be chosen. Gallery: add (multiple), move earlier/later, remove, per-image alt (default: the file's Media Library alternative text; `requireAlt`/decorative as in the image block), caption, focal point, layout and columns. Video/audio: choose/replace, title, caption, loop (+ muted and poster for video), WebVTT tracks (kind, language defaulting to the content locale, label, one default).
- Field readiness and edits (`editor/input-tracking.mjs`): the field reports content to the form only after the person edited it (Editor.js also reports its normalisation of stored content on the first render). User input (`pointerdown`, `keydown`, `input`, `paste`, `drop`, capture phase on the holder) is tracked from before Editor.js renders, and edits made while Editor.js was starting are saved on `onReady`; after the Content Manager's create -> edit redirect several fields mount at once and text typed before the field's own effects ran used to stay out of the form (Save stayed disabled). The holder (`[data-testid="magic-editor-x"]`) carries `aria-busy="true"` while loading and `data-mex-ready="true"` once Editor.js is ready and every listener is attached; browser tests wait for `data-mex-ready` instead of sleeping.
- Editor styles (`editor/tools/styles.js`) are one global style rendered by the first mounted field only (`editor/style-owners.mjs`, `SharedEditorStyles`); one copy per field made styled-components rebuild every copy on each mount and unmount (seconds of blocked main thread on pages with several fields).
- `apply-remote.js`: default tune values count as "no tune" in `blockKey`; more than 150 changed blocks (and a quarter of the document) are applied with one `render` instead of per-block updates (Editor.js notifies every block on each mutation).

## Block comments (2.3)

- Content type `plugin::magic-editor-x.comment` (table `magic_editor_comments`, hidden from the Content Manager and the Content-Type Builder, no Content API route): `contentType`, `entryId`, `entryLocale` (null for types without i18n), `fieldName` (the field identity of the version / room key `uid|documentId|locale|field` as columns; 2.4: `<path without indices>#<fieldKey>` inside repeatable components and dynamic zones), `blockId` (Editor.js block id, `/^[A-Za-z0-9_-]{1,64}$/`), `threadId` (documentId of the root; null on the root), `excerpt` (root only, plain one-line text, max 200), `body` (plain text, max 4000 after `normalizeCommentBody`: CRLF to LF, tabs to spaces, C0/C1 controls, bidi overrides and zero-width marks removed, at most two blank lines), `authorId` (admin id) + `authorName` (name snapshot), `editedAt`, `resolved`, `resolvedAt`, `resolvedById` + `resolvedByName`. Access through `services/comments.js` (query engine).
- API shapes: thread `{ id, blockId, excerpt, status: 'open'|'resolved', resolvedAt, resolvedBy: { name }|null, createdAt, updatedAt (latest activity), comments: [comment] }`; comment `{ id, threadId, body, author: { name|null, own, deleted }, createdAt, updatedAt, editedAt }`. Admin ids are never returned; `own` tells the caller whether they wrote it. Comments are never part of the field value, version history or Content API output.
- Rules: every route needs `access` + `comments.read` and Content Manager read on the document, locale and field (`services/access.js` `checkField`, 404 otherwise; a comment id of another document answers 404 too). Commenting, replying, resolving and reopening need `comments.write` but no update right (reviewers). Editing: author only. Deleting: own comment with `comments.write`; anyone's, or a thread with replies by other people, with `comments.moderate`. Limits: `comments.perMinute` new comments per admin (counter `comments:<adminId>` in `magic_editor_x_counters`, 429), 1000 comments per field and locale, 200 replies per thread (400 `TOO_MANY_COMMENTS`). Handlers log nothing.
- Retention (`utils/comment-retention.js`): a Document Service middleware deletes the comments of every document locale a `delete` removed (`result.entries[].locale`), after the delete; an `admin::user` `afterDelete` lifecycle clears `authorId`/`authorName` and `resolvedById`/`resolvedByName` of the deleted admin (the text stays, shown as "Deleted user"). Rows written around the Document Service (raw SQL, `db.query`) are not cleaned up.
- Admin: toolbar toggle with the open-thread count, `CommentsPanel` (pattern of the quality panel: new thread on a chosen block, open threads first, detached threads (block no longer in the document) still readable and resolvable, "Show resolved threads", reply, resolve/reopen, edit/delete own with ConfirmDialog, live region) and `CommentMarkers` (button with the open-thread count at the inline end of each block, rendered next to the Editor.js holder, never inside it). `useComments` polls `GET /comments` every 15 s while the field is on screen and the tab visible (8 s with the panel open), on window focus and after every own action; the database is the source of truth, so it works across processes. Config `comments.enabled: false` hides the UI and the routes answer 404.

Audit trail:

- What is recorded (never content, e-mail addresses, IP addresses or tokens): `event`, target `{ uid, documentId, locale, field }`, `counts` (non-negative integers, at most 12 keys), `blockIds` (at most 20 Editor.js ids), `meta` (at most 8 keys of identifier-like strings `/^[A-Za-z0-9_.:-]{0,64}$/` or lists of them), actor, time. `shared/audit.mjs` `cleanAuditInput` enforces the shape for every caller. Events: `entry.create|update|publish|unpublish|discard|delete` (per changed editor field, counts `{ added, removed, changed, moved, blocks }`), `version.create|restore|rename` (`counts.version`), `ai.action` (`meta.action`, `counts.segments` or `counts.images`), `comment.create|reply|resolve|reopen|delete|moderate` (`meta.threadId`, the block id), `template.create|update|delete` and `synced.create|update|delete|restore` (`counts.blocks`, `meta.kind`), `settings.update` (`meta.keys`: the submitted top-level keys, never values), `linkcheck.run` (`counts.documents|checked|problems|pruned`, `meta.trigger`, `meta.complete`). Other features may add `<area>.<verb>` events.
- Service for other features: `strapi.plugin('magic-editor-x').service('audit').record({ event, target?: { uid?, documentId?, locale?, field? }, counts?, blockIds?, meta?, actor? }) -> Promise<boolean>` (never throws; `recordMany([...])` for several). `actor`: omitted = the admin of the current request (`strapi.requestContext`, admin routes only), `'system'`, or an admin user object / `{ id, name }`. Content API writes are recorded with `actor.kind: 'api'` and no id. Server code can use `utils/audit-record.js` `recordAudit(strapi, input)`, which also tolerates a missing service.
- Field identity: `shared/audit.mjs` `fieldIdentity(path, value)` is the one place that decides it (2.4 field identity contract): the path for top-level and single-component fields, `<path without indices>#<fieldKey>` for positional fields whose value has a `fieldKey`, else the positional path. `GET /audit` accepts `fieldKey` next to `field`.
- Field changes: `utils/audit-trail.js` registers a Document Service middleware for `api::` types with editor fields. It reads the editor fields (only them: `guardQuery` fields + populate) of the affected versions before and after `create`, `update`, `publish`, `unpublish`, `discardDraft` and `delete` (draft for Draft & Publish writes, published for publish/unpublish and types without Draft & Publish, every locale the call touches) and records one event per changed field. `fieldChanges(before, after)` compares blocks by id and a JSON fingerprint (no word diff): linear, about 6 ms for 5000 blocks (`npm run bench` operation `auditChanges`). Writes around the Document Service are not recorded. A failure is logged without data and never blocks the write.
- Storage: table `magic_editor_x_audit (id bigint, created_at ms, event, uid, document_id, locale, field, actor_id, actor_name, actor_kind 'admin'|'api'|'system'|'deleted', counts JSON, block_ids JSON, meta JSON)` created in `services/store.js`, indexes `(uid, document_id, locale, id)`, `(created_at)`, `(actor_id, id)`. A table instead of a content type: append-only, high volume, no documentId, publication or Content Manager needed (like the link check tables). Inserts go through `strapi.db.transaction`, which joins the caller's transaction (no second SQLite connection, rolled back with it).
- Config: `audit.enabled` (default `true`: the trail holds no content and answers "who changed this" for editors and owners; `false` stops recording and the middleware's reads), `audit.retentionDays` (default 180, 0 keeps everything, max 3660). Pruning: once an hour one process (one-time key `audit:prune:<hour>` in `magic_editor_x_locks`) deletes older rows in batches of 1000 (at most 50 per run). A deleted admin user's rows keep the event and lose `actor_id`/`actor_name` (`actor_kind: 'deleted'`, shown as "Deleted user"; `admin::user` `afterDelete` lifecycle).
- Access (decided): with `field` (+ `uid`, `documentId`) the listing is field-scoped and needs `audit.read` plus Content Manager read on the document, locale and field (`services/access.js` `checkField`, 404 otherwise); actors carry `{ kind, name, own, deleted }` without ids. Without `field` (global, also filtered by type or document) it needs `audit.read` + `settings.read` (403 otherwise), because it spans documents; actors also carry `id` (for the actor filter). Records hold no content, so a global reader learns which documents and fields changed, by whom and how many blocks, not what.
- Strapi Enterprise Audit Logs: when `strapi.has('audit-logs-lifecycle')` (Enterprise license with the feature, as `@strapi/review-workflows` checks it), bootstrap registers every event as `magic-editor-x.<event>` with `registerEvent(name, transform)` (`resource: { type: 'magic-editor-x', uid, id: documentId }`, `details: { locale, field, counts, blockIds, meta }`; other events on first use) and `record` emits it on `strapi.eventHub`; Strapi stores it only for admin requests and with its own actor data. Without the feature nothing is emitted; webhooks never fire for these names.
- Admin: Settings > Magic Editor X > Audit trail (`pages/AuditPage`, link permission `audit.read`; the page needs `settings.read` too): filters (event, actor, content type uid, document id, date range) and page in the URL, DS `Table` from the `large` breakpoint, a card list below, admin `Pagination`, empty/loading/error states, "Recording is off" when disabled. The version history modal gets "Versions" / "Activity" tabs for admins with `audit.read` (`FieldActivity`, `GET /audit?uid&documentId&locale&field`, 20 per page, "Show older activity"). Restoring a field version calls `GET /history/:id?intent=restore`, which records `version.restore` when the caller may update the document.

Synced source versions:

## Templates, block patterns and the in-field preview (2.3)

- Content type `plugin::magic-editor-x.template` (table `magic_editor_templates`, hidden from the Content Manager and the Content-Type Builder, no Content API route): `name` (max 100), `description`, `kind` (`template` = whole starting content \| `pattern` = insertable block sequence), `blocks` (Editor.js document), `scope` (`{ all, presets: [preset name], fields: [{ uid, field }] }`, field paths without indices such as `sections.body`), `enabled`, `sortOrder`, `createdByName` (display name snapshot; no admin id is stored), timestamps. Access through `services/templates.js` (query engine).
- API shape: `{ id, name, description, kind, blocks, blockCount, scope, enabled, sortOrder, createdBy: { name } | null, createdAt, updatedAt }`.
- Writes: strict zod schema, then `cleanEditorValue(blocks, { rawHtml })` with `rawHtml` `sanitize` (or `disable` when the plugin disables raw HTML; templates never keep unsanitised raw HTML), at least 1 and at most 200 blocks, 256 KiB of JSON, at most 500 templates; scope fields must be Magic Editor X fields of `api::` types. Handlers log nothing.
- Scope (`shared/templates.mjs` `templateMatchesTarget`): `all`, or the field's preset name (`resolveFieldPreset(options).name`) is in `presets`, or `{ uid, field without indices }` is in `fields`. The editor list requires `access` and Content Manager read on the content type (404 otherwise).

The new document goes through `replaceContent` (Editor.js block API, the shared Yjs document, undo). Managers save the selection (block selection bar) or the whole field (insert dialog) as a new template (`POST /templates`).
- Settings > Magic Editor X > Templates (`pages/TemplatesPage`, link permission `templates.manage`): list (enable, preview, edit, duplicate, reorder, delete with ConfirmDialog), create/edit view with an embedded editor (`EditorFieldBody` with an empty target: no collaboration, history, comments or template insertion) and the Blocker.
- Preview (`FieldPreview`, `components/RenderedContent`): toolbar toggle and Ctrl/Cmd+Alt+P; renders `currentData` with `MagicEditorXContent` from `shared/frameworks/react.mjs` (code line numbers on); raw HTML only when the plugin keeps raw HTML and the preset allows `raw`, then sanitised again with a strict DOMPurify profile; embeds become a labelled link placeholder (no iframe); tables get their own scroll region; clicks on links are prevented. The editor stays mounted (hidden) while the preview is shown; works for read-only users.

## Synced blocks (2.3)

- Source: a row of `plugin::magic-editor-x.template` with `kind: 'synced'` (same fields, limits, sanitising, scope, `enabled`, order and `templates.manage` permission as templates and patterns; managed on Settings > Templates with the kind filter). Chosen over a content type of its own because the stored shape, validation, settings UI and permission are identical; the differences are kind-specific branches in `services/templates.js`. Rules: a source never contains a `synced` block (400 `fieldErrors.blocks` "A synced block cannot contain another synced block"; the admin form checks it too), so references cannot nest or form cycles; the kind of a source never changes and a template/pattern never becomes a source (400 `fieldErrors.kind`); `enabled: false` only stops offering it for insertion (`GET /templates/:id` still returns it, references keep rendering it). Sources are not localised and have no Draft & Publish: a saved change is live in published output at once (that is the point of the feature).
- Field value: block `{ type: 'synced', data: { ref: <source documentId> } }`, nothing else (policy: invalid refs become `''`; schema `data_synced`; types `SyncedData`). Stored as `{ ref, _mex: 1 }` (built-in marker, see Media Library blocks > Compatibility): a pre-2.3 custom block named `synced` keeps the generic policy and its own tool; new custom blocks cannot use the name. Presets: in `full` and `article`, not in `basic`/`minimal`; `allowedBlocks` may list it; `checkPreset` reports `BLOCK_NOT_ALLOWED`. The Yjs guard refuses a built-in synced block whose data is not exactly `{ ref, _mex? }` with a documentId (or `''`). `computeStats` counts no text for it (limits count the reference as one block).
- Expansion (`shared/synced.mjs` `expandSynced(data, lookup, { filter, maxBlocks, maxBytes })`): each reference is replaced by a deep copy of the source blocks with ids `<refBlockId>-<sourceBlockId>` (hashed when longer than 64 characters, unique in the document); references inside a source are dropped; toggle `items` counts of enclosing toggles are recomputed (`replaceBlocks`, `toBlockTree`/`fromBlockTree`); a missing source, a source with no allowed block, or one that would exceed 5000 blocks / ~5 MiB expands to nothing. `origins` maps copied ids to the reference.
- Preset interaction (decided: filter, not refuse): `templates.mjs` `filterSyncedForField(blocks, preset)` leaves out blocks of types the containing field does not allow (a disallowed toggle's content stays), fixes heading levels and links like "Fix automatically", leaves out unfixable blocks and images without alt in `requireAlt` fields. Refusing the field save was rejected because a source can change after the field was saved. The editor view shows "N blocks of the source are not allowed in this field and left out".
- Content API / GraphQL (`services/references.js` `expandAll`, before reference collection): one query for all sources of a response (`templates.syncedSources(ids)`, at most `SYNCED_LIMITS.refsPerResponse` = 100 distinct sources), each source cleaned with the containing field's sanitiser (`cleanEditorValue` with the configured `rawHtml` and the preset's inline tags) and filtered by its preset (`render-output.js` and `graphql.js` pass `attribute.options`). Permission model: sources are shared editorial content an author embedded on purpose, so they are expanded for every caller who can read the containing entry; internal links, mentions, embedded entries and media inside them are resolved with the caller's permissions like any other reference (unreadable targets become plain text / `null`). `json` output has the copied blocks inline with `syncedFrom: <ref>`; without `?mex` the stored reference is returned unchanged.
- Renderers: option `synced` (`{ [ref]: document | blocks }`, a `Map`, or `(ref) => document | blocks | null`) in `renderHtml`/`renderText`/`renderMarkdown`/`renderTree` and the React/Vue components (`prepareBlocks` expands before cleaning, so the copies are cleaned and rendered like any block and a `toc` lists their headings); without it, or for an unknown ref, a synced block renders nothing.
- Usage (`GET /templates/:id/usage`, `templates.usage`): a bounded scan of the stored data (every `api::` type with editor fields, top level/components/dynamic zones, drafts and published versions, all locales, batches of 100 by id; `USAGE_LIMITS` 200,000 rows / 20 s, then `complete: false`) plus templates/patterns that contain the reference. A scan instead of an index table: it reads what is stored, so edits through the Content Manager, the Content API, scripts or imports are all counted, without write hooks on publish, discard, delete or locale operations. Counts only.
- History: versions store the reference only; restoring restores the reference; old versions render the current source (like a component). The diff shows "Synced block <name>" (`syncedDiffRefs`; `leafKind` treats `ref` as a value). Source versions are kept since 2.4 (see "Audit trail, synced source versions and the link check").
- Admin: tool `tools/synced.js` (no toolbox entry; inserted from the "Insert template" dialog's "Synced blocks" section, offered only where the preset allows `synced`; `GET /templates?uid&field` filters them). The tool hands its `data-mutation-free` element to the field (`config.mount`), which renders `SyncedBlockView` through a React portal: "Synced block: <name>", the source rendered with `RenderedContent` after `filterSyncedForField`, "Edit source" (`LinkButton isExternal` to `/settings/magic-editor-x/templates?edit=<id>`, only with `templates.manage`), "Detach" (editors: the reference is replaced by a copy through `prepareInsertion` and `replaceContent`, fresh ids, one undo step), "Synced block removed" when the source is gone (404). Sources load through `editor/synced-store.js` (one cache per page, shared requests, refresh on focus/visibility, every 30 s while visible, `MAX_AGE_MS` 15 s). The in-field preview passes the sources as `options.synced`. Keydown on the view's controls does not reach Editor.js.

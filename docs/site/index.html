Strapi 5 plugin

Blocks, history and live editing in the Content Manager.

Magic Editor X adds an Editor.js field to Strapi 5. Write with headings, lists, tables, formulas, footnotes, code, images from the Media Library, embeds and your own custom blocks, discuss and suggest changes, keep versions of every field and edit together in real time. Free under the MIT license, with nothing to activate and no limits.

What's new in 2.4

No breaking changes: stored content keeps working and Editor.js stays at 2.31.7. The full list, with notes on existing data, is in the CHANGELOG.

  • A short field toolbar: undo, redo, a More tools menu (Review, Write, View) and full screen. Tools appear only where they can work.
  • Tables with a header row and header column, alignment per column, merged cells and a caption; spreadsheet and Word paste keep them.
  • Formulas in TeX as a block or inside text, rendered as MathML, and footnotes numbered in reading order.
  • Comments on selected text that stay on the passage while people edit, @mentions of colleagues, and a Mentions and replies widget on the admin home page, with optional e-mails.
  • Block suggestions: reviewers propose changes in a separate copy, editors accept or reject each block.
  • AI for chosen blocks: rewrite, shorten, translate or change the tone of just those blocks, with a word diff before applying.
  • An audit trail of who changed what and when, without content; versions of synced blocks; Run now and a time zone for the scheduled link check.
  • Fields in repeatable components and dynamic zones have history, comments and live editing again (stable fieldKey).
  • @ in text inserts a mention, code blocks get a file name, pasted videos and audio are copied into the Media Library.
  • Strapi AI translations send only text and keep the field structure; Releases show entries the publishing guard refuses as not ready.

Also fixed: a collaboration bug that could delete blocks an editor had not rendered yet when it typed right after joining a room. Why the plugin stays on Editor.js: engine decision.

Features

Everything is free in every installation, without telemetry. The plugin makes outgoing requests only for link previews, images by URL, the external link check and the AI provider and LanguageTool server the owner configured.

Editor.js blocks

Paragraph, heading, nested list, checklist, quote, warning, alert, toggle, delimiter, tables with merged cells, math, code with syntax highlighting and file names, raw HTML, embeds, link previews, person cards, buttons, footnotes and a table of contents with stable heading anchors. Block names and data stay the same as in 1.x.

Media library

Upload images and attachments into the Strapi Media Library or pick existing files. Gallery (grid or carousel), video and audio blocks with captions and WebVTT tracks, alternative texts and a focal point that frontends keep visible when they crop.

Custom blocks

Define simple blocks with fields and an HTML template, or blocks that embed an entry of another content type. Import and export them as JSON. Blocks that need code are defined once with the block SDK (magic-editor-x/blocks).

Field presets

Per field: allowed blocks and heading levels, character and block limits, required alternative text, allowed links, AI and live editing on or off, and a publishing guard. Enforced on every save and over the live channel.

Render anywhere

magic-editor-x/render turns stored content into HTML, plain text or Markdown without dependencies and safe against XSS; magic-editor-x/react and magic-editor-x/vue render it as components (React 18 and 19, Vue 3.5). A JSON Schema and TypeScript types describe the data.

Paste and migrate

Word, Google Docs, web pages and Markdown paste as real blocks. A CLI migrates Strapi Blocks, Markdown and HTML fields with a dry run and a report.

Write faster

Markdown shortcuts, find and replace, keyboard shortcut help, focus mode, actions for several selected blocks, reading time, mentions of entries (also with @) and a rendered preview of the field, behind a short toolbar with one More tools menu.

Version history

Named versions, a word-level comparison with the current content and restore of the whole field or a single block, also for fields in repeatable components and dynamic zones. Automatic versions are created while people edit live; synced blocks keep versions too.

Quality checks

Accessibility lint (alternative texts, heading order, link texts, table headers, contrast, video captions) and a link check, an optional scheduled check of every external link (one process in a cluster runs it), and an optional publishing guard.

Live collaboration

Several admins edit the same field at once: texts, table cells, list items, tunes and custom fields merge without conflicts, with coloured carets, presence, per-user undo, offline editing and read-only viewers, also across several servers without sticky sessions.

AI assistant

Improve, correct, shorten, expand, summarize, simplify, translate or change the tone of selected text or chosen blocks with Anthropic, OpenAI or an OpenAI-compatible server and your own key. Optional: alternative text suggestions for images and translate or summarize a whole field.

Templates, patterns and synced blocks

Reusable starting content and groups of blocks per field or preset, inserted from the toolbar. Synced blocks are edited once and every field that uses them shows the change.

Comments and mentions

Threads on single blocks or on selected text, with replies, resolve and reopen and @mentions of colleagues who can read the field. Reviewers can comment without update rights; comments are never part of the content or the API output.

Suggestions

Reviewers propose block changes in a separate copy of the field; editors accept or reject each one. Nothing reaches the entry before it is accepted and saved.

Audit trail

Who changed which field, version, comment, template or setting, and when, with counts and block ids but never the content. Kept 180 days by default.

Content API and GraphQL output

?mex=html|text|markdown|json and GraphQL <field>Rendered / <field>Resolved return rendered or resolved content. Links, mentions, embedded entries, media and synced blocks are resolved with the caller's permissions.

Grammar check

Spelling and grammar of a whole field with your own or a hosted LanguageTool server, off until the owner turns it on, with its own permission.

Screens

All screenshots use synthetic data (acceptance host: Strapi 5.61.1).

Install

  1. 1

    Add the package

    npm install magic-editor-x

  2. 2

    Enable it

    Add 'magic-editor-x': { enabled: true } to config/plugins, then run npm run build and restart.

  3. 3

    Add the field

    In the Content-Type Builder choose Custom > Magic Editor X. Grant the plugin actions to your roles.

Collaboration on several servers

Live collaboration works with several Node processes behind a load balancer without sticky sessions, for example two replicas with four processes each. No Redis is needed.

  • The browser uses the WebSocket transport only; allow WebSocket upgrades on collaboration.path.
  • All processes share the database and the same ADMIN_JWT_SECRET, which signs the one-time session tokens.
  • Every edit is stored before it is acknowledged; other processes pick it up every collaboration.pollIntervalMs.
  • Room seeding, compaction, automatic versions and cleanup run once across all processes; a room with unsaved edits gets a final version before it is cleaned up.
  • Permission changes reach every process within about a second; AI and session rate limits are shared by all processes.
  • Tested with 8 processes, 12 concurrent editors, killed and restarted processes, network partitions and offline clients: no edit lost.

AI assistant and grammar check

Off until an administrator configures a provider in Settings > Magic Editor X > Configuration.

ProviderDefault model (2026-11-11)
Anthropic Messages APIclaude-opus-5-5
OpenAI Chat Completionsgpt-6-luna
OpenAI-compatible server (Ollama, vLLM, LM Studio)you name the model

The key stays on the server, encrypted at rest. Only the selected text, or the text of the chosen blocks, and a fixed instruction are sent; the editor sees a word diff before anything changes. Private base URLs need ai.allowPrivateBaseUrl.

Two more features use the same provider, each behind its own switch in Settings, off by default: Send images to the AI provider (alternative text suggestions for image blocks and gallery images; one image of at most 1568 px is sent) and Allow whole-field AI actions (translate or summarize a field; the inline text of every block is sent). Results are suggestions the editor reviews; fields with disableAi are never sent.

The grammar check sends the plain text of a field to a LanguageTool server you choose (self-hosted or hosted) when an editor with grammar.use presses Check grammar. It is off until an owner enters the server in Settings; a hosted account's key is encrypted like the AI key.

Content API and GraphQL output

Without extra parameters the Content API returns the stored Editor.js JSON. Add ?mex= to a GET request to get each Magic Editor X field rendered or resolved.

RequestField value
?mex=htmlRendered HTML string
?mex=textPlain text
?mex=markdownMarkdown
?mex=jsonThe stored document with resolved references
GraphQL bodyRendered(format: HTML)Rendered string (HTML, TEXT, MARKDOWN), with @strapi/plugin-graphql
GraphQL bodyResolvedJSON with resolved references
  • Internal links, mentions, embedded entries, Media Library files and synced blocks are resolved with the caller's own permissions; targets the caller cannot read are handled like missing ones.
  • Published versions are used unless the request asks for status=draft; every row passes Strapi's output sanitising.
  • mex is registered with Strapi's contentAPI.addQueryParams, so it works with strict parameters; admin and plugin routes are never changed.
  • At most 500 references and 5 seconds per response.

Security

  • Every value is normalised and sanitised on save, from the Content Manager, the Content API or code.
  • Link previews, images and media by URL only reach public addresses (or exact origins the owner lists), pinned after DNS resolution, with size, type and time limits.
  • Uploads are checked by their content and stored through the Media Library.
  • Collaboration tokens are signed, short-lived and single-use; every update is checked before it is stored or relayed; remote content is sanitised before it is shown; viewers cannot write.
  • The AI and LanguageTool keys are encrypted with AES-256-GCM and never returned; logs contain no content.
  • Content API and GraphQL output resolves references with the caller's permissions and never reveals entries the caller cannot read.
  • The React and Vue components share one render tree with renderHtml: text is escaped, URLs are validated, raw HTML only through your own sanitiser.
  • AI images, whole-field AI, the grammar check and the scheduled link check are off by default and send nothing until the owner turns them on.
  • Comments and suggestions need their own permissions and Content Manager read on the document; they never appear in the content or the API output.
  • Formulas are rendered as MathML through an allow-list (no links, styles, ids or event handlers); pasted videos and audio are fetched only from public addresses and checked by their first bytes.
  • Mentions reach only people who can read the field; notifications hold ids only and mention e-mails never contain the comment text.
  • Suggestions are cleaned and checked against the field's rules; accepting needs update access and each suggestion is decided once.
  • The audit trail keeps ids and counts, never content, e-mail or IP addresses.
  • Strapi AI translations receive only the text of a field; the publishing guard also covers direct published writes and Releases readiness.
  • Reviews: security-audit-2.4.md and security-audit-2.3.md.

Migrating from 1.x

Stored content keeps working. Routes, permissions and configuration keys changed, the license system is gone and collaboration grants follow Content Manager permissions. The step-by-step guide is in the CHANGELOG.

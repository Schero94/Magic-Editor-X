Strapi 5 plugin

Blocks, history and live editing in the Content Manager.

Magic Editor X adds an Editor.js field to Strapi 5. Write with headings, lists, tables, code, images from the Media Library, embeds and your own custom blocks, keep versions of every field and edit together in real time. Free under the MIT license, with nothing to activate and no limits.

Features

Everything is free in every installation. The plugin makes outgoing requests only for link previews, images by URL and the AI provider you configure.

Editor.js blocks

Paragraph, heading, nested list, checklist, quote, warning, alert, toggle, delimiter, table, code, code with syntax highlighting, raw HTML, embeds, link previews, person cards and buttons. Block names and data stay the same as in 1.x.

Media library

Upload images and attachments into the Strapi Media Library or pick existing images. Files are checked by their content and stored with the admin as creator.

Custom blocks

Define simple blocks with fields and an HTML template, or blocks that embed an entry of another content type. Import and export them as JSON.

Version history

Save versions of a field, preview and restore them. Automatic versions are created while people edit live.

Live collaboration

Several admins edit the same field with character-level merging, presence avatars and read-only viewers, also across several servers without sticky sessions.

AI assistant

Improve, correct, shorten, expand, summarize, simplify, translate or change the tone of selected text with Anthropic, OpenAI or an OpenAI-compatible server and your own key.

Install

  1. 1

    Add the package

    npm install magic-editor-x

  2. 2

    Enable it

    Add 'magic-editor-x': { enabled: true } to config/plugins, then run npm run build and restart.

  3. 3

    Add the field

    In the Content-Type Builder choose Custom > Magic Editor X. Grant the plugin actions to your roles.

Collaboration on several servers

Live collaboration works with several Node processes behind a load balancer without sticky sessions, for example two replicas with four processes each. No Redis is needed.

  • The browser uses the WebSocket transport only; allow WebSocket upgrades on collaboration.path.
  • All processes share the database and the same ADMIN_JWT_SECRET, which signs the one-time session tokens.
  • Every edit is stored before it is acknowledged; other processes pick it up every collaboration.pollIntervalMs.
  • Room seeding, compaction, automatic versions and cleanup run once across all processes.

API and permissions

All routes are admin routes under /magic-editor-x. Version history and collaboration also follow the Content Manager permissions of each document, locale and field.

ActionGates
plugin::magic-editor-x.accessEditor features, uploads (with Media Library create), link previews, version history
plugin::magic-editor-x.collaborateJoining live rooms
plugin::magic-editor-x.ai.useAI assistant
plugin::magic-editor-x.custom-blocks.manageSettings > Custom blocks
plugin::magic-editor-x.settings.readSettings > Configuration (read)
plugin::magic-editor-x.settings.updateSaving settings, testing the AI connection

The route table, the data format of every block and the collaboration protocol are in the README and AGENTS.md.

Security

  • Every value is normalised and sanitised on save, from the Content Manager, the Content API or code.
  • Link previews and images by URL only reach public addresses, pinned after DNS resolution, with size, type and time limits.
  • Uploads are checked by their content and stored through the Media Library.
  • Collaboration tokens are signed, short-lived and single-use; viewers cannot write.
  • The AI key is encrypted with AES-256-GCM and never returned; logs contain no content.

Migrating from 1.x

Stored content keeps working. Routes, permissions and configuration keys changed, the license system is gone and collaboration grants follow Content Manager permissions. The step-by-step guide is in the CHANGELOG.

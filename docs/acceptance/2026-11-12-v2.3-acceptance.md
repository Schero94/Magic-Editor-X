# Magic Editor X 2.3 acceptance (2026-11-12)

Final build under test: the published 2.3.0 code (`origin/main` dca5697, identical in code to `feat/2.3` at 6984680) plus the fixes of this acceptance on `fix/2.3.1` (positional editor fields, see below; last code commit 580b555), with every 2.3 feature (render tree and React/Vue renderers, Content API `?mex=` and GraphQL, block SDK, gallery/video/audio and focal points, table of contents, mentions and code block, templates, patterns and preview, synced blocks, block comments, scheduled link check, AI alternative text, whole-field AI and the LanguageTool grammar check, version diff fix), packed with `npm pack` (package version 2.3.0) and installed from the tarball into one isolated Strapi 5.61.1 host: port 1461 on SQLite, port 1462 on PostgreSQL 16, and the 8-process cluster on PostgreSQL. Node 22.23.1, Playwright 1.65 (Chromium). Random `.env` secrets, outgoing network blocked in every Strapi process (`-r block-egress.cjs`), synthetic admins and content only, the AI provider and the LanguageTool server local fakes. Host setup as in CONTRIBUTING.md (updated by this acceptance): content types with `summary` (`basic` preset, `requireAlt`, `maxCharacters: 400`, `linkTargets: 'internal'`, `disableAi`, `disableCollaboration`, `publishGuard`), `teaser` (`minimal`), `legacy` Blocks, `notes` Markdown, `migrated`, `sections` component and `zone` dynamic zone; the SDK example block `calloutCard` registered by the host; GraphQL, `strictParams`, admin login limit 20; plugin config with the fake AI provider, `languageTool.allowPrivateBaseUrl`, the link check with `allowPrivateOrigins: ['http://127.0.0.1:1561']` and the schedule on; five seeded admins (editor, author, reviewer, reader, writer) and the locale `de`; `summary` also has `disableGrammar`, and the integration runs start the host with `MEX_LEGACY_BLOCKS=true` (a pre-2.3 Settings block named `toc`).

## Bugs found by this acceptance and fixed

- Editor fields inside a repeatable component or a dynamic zone used live collaboration under their positional path (`sections.0.body`). After an entry whose editor had been opened was removed (or entries were moved) before saving, the next entry joined the old room and showed the removed entry's content; typing there would have saved it into the wrong entry. Positional fields are now edited without a live room (`admin/src/editor/field-path.mjs`, `tests/field-path.test.mjs`; fix/2.3.1). Verified in the browser: open the first of two entries, delete it, open the remaining one: before the fix "Section one", after it "Section two".
- Version history and block comments were keyed by the same positional path: after an entry was removed or moved and the document saved, the versions and comments of `sections.0.body` belonged to the entry that was there before (checked through the API: a version made for entry A was listed for entry B once A was removed). The admin now offers neither for positional fields (580b555, `tests/field-path.test.mjs`), as in 2.2 where these fields had no history; top-level fields and single components keep both. Keying by component entry is left for a later release.
- The gallery offered no AI alternative text suggestion (fixed before 2.3.0; `s23-gallery-alt`).
- The security review cited wrong or incomplete tests for six findings (corrected before 2.3.0).
- MEX-23-12 was only covered through the link report; `tests/integration/components.test.mjs` covers history and collaboration for component and zone fields (it fails against 2.2.0).
- CONTRIBUTING.md lacked the host setup of the 2.3 suites.

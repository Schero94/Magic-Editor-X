# Magic Editor X 2.3 acceptance (2026-11-12)

Build under test: branch `feat/2.3` with every 2.3 feature merged (render tree and React/Vue renderers, Content API `?mex=` and GraphQL, block SDK, gallery/video/audio and focal points, table of contents, mentions and code block, templates, patterns and preview, synced blocks, block comments, scheduled link check, AI alternative text, whole-field AI and the LanguageTool grammar check, version diff fix), packed with `npm pack` (the package version stays 2.2.0 until semantic-release sets 2.3.0) and installed from the tarball into one isolated Strapi 5.61.1 host: port 1461 on SQLite, port 1462 on PostgreSQL 16, and the 8-process cluster on PostgreSQL. Node 22.23.1, Playwright 1.65 (Chromium). Random `.env` secrets, outgoing network blocked in every Strapi process (`-r block-egress.cjs`), synthetic admins and content only, the AI provider and the LanguageTool server local fakes. Host setup as in CONTRIBUTING.md (updated by this acceptance): content types with `summary` (`basic` preset, `requireAlt`, `maxCharacters: 400`, `linkTargets: 'internal'`, `disableAi`, `disableCollaboration`, `publishGuard`), `teaser` (`minimal`), `legacy` Blocks, `notes` Markdown, `migrated`, `sections` component and `zone` dynamic zone; the SDK example block `calloutCard` registered by the host; GraphQL, `strictParams`, admin login limit 20; plugin config with the fake AI provider, `languageTool.allowPrivateBaseUrl`, the link check with `allowPrivateOrigins: ['http://127.0.0.1:1561']` and the schedule on; five seeded admins (editor, author, reviewer, reader, writer) and the locale `de`.

Notes on the runs:

- `s22-matrix` checks that external links are "Not checked" while the owner has not turned the link check on; the 2.3 host turns it on for the scheduled check, so this scenario ran against the same host restarted with the link check off (`MEX_LINKS=false`, `MEX_LINK_SCHEDULE=false`). The plugin refuses to start with the schedule on and the link check off (`invalid configuration for: qualityChecks.externalLinks.schedule.enabled`), as intended.
- Scenario fixes, not product fixes: `s23-ai` addressed the image of a block by `img`, which now also matches the focal point preview of the merged media feature; `s23-struct` compared stored JSON by key order, which PostgreSQL `jsonb` does not keep; `s23-settings`/`s23-schedule` matched "On" case-sensitively, the merged Settings page shows the state as a badge ("ON"); the console filters of `s23-media`, `s23-sdk` and `s23-ai` now ignore the aborted `/admin/information` request that Strapi cancels on navigation.
- `s22-preset` failed twice in about a dozen runs at its last step: the text typed into the `summary` field right after the save redirect did not arrive (the field still had 75 characters), so Save stayed disabled. Seven repeated runs in a row on SQLite and PostgreSQL passed. The 2.2 acceptance recorded a similar timing failure of this scenario; the root cause (typing during the editor re-mount after the create → edit redirect) is not proven.
- `s22-matrix` and `s22-preset` in one round ran in Portuguese because the locale sweep had stored the admin language in the saved session; they passed after the session was reset.

Measurements (`measure.js`): no document overflow at any width in light or dark. Remaining `elementsOutsideViewport` at 390/320 px are lines of code blocks (inside their own scrolling `pre`) and the toolbars of Strapi's own Blocks and Markdown fields (`legacy`, `notes`), which Strapi clips. Small targets: the Design System `Switch` (40 × 24 px) in Settings > Templates below 768 px and the DS `Radio` (20 × 20 px) in the template editor are Design System sizes with clickable labels; they meet WCAG 2.5.8 (24 × 24 or an equivalent target) but not the workbench's stricter 32 px rule for narrow screens, and are recorded as a Design System limitation. The editor's own "Decorative image", "Play in a loop", "Start muted" and "Show by default" checkboxes (13 × 13 px) are wrapped in their labels, which are the targets. The other small targets are Strapi core ("Back", the UID "Regenerate" button) and inline text links.

Console: no errors or warnings from plugin code. Remaining messages also appear on native Content Manager pages or come from Strapi core: 404 for `/content-manager/preview/url/…` and `/i18n/ai-localization-jobs/…`, the aborted `/admin/information` request on navigation, 401s when a stored session expires, a 404 for a synced block whose source was deleted on purpose, and the styled-components warning about an unknown prop `attribute`.

Attribution of the `attribute` warning: it appears once on the Content Manager create page of `plugin::users-permissions.user` (no Magic Editor X field), of the article and of the category with 2.3, with 2.2.0 (tarball built from `fd9b014`, same host and database), and on the users-permissions page of the same host started with Magic Editor X disabled and no plugin content types. No frame of its stack belongs to the plugin. It is Strapi core noise.

Locales: besides the sweep above, the only untranslated string found is Strapi core's UID hint "This value is unique for the selected locale" in Portuguese.

## Bugs found by this acceptance and fixed

- The gallery offered no AI alternative text suggestion: the image block passed `suggestAltText` to its alternative text control, the gallery did not. Gallery images now get the same control (per image, with the image's Media Library id). Regression test in `tests/admin-source-contract.test.mjs`, browser check `s23-gallery-alt`.
- The security review cited wrong or incomplete tests for MEX-23-02, -03, -07, -10, -12 and -14 (for example `server-units.test.mjs` for the component permission fix, which it does not cover, and a "2,242-case" equality test that was a one-off run). Corrected in `docs/security-audit-2.3.md`.
- MEX-23-12 (component fields answering 404) was only covered through the link report. `tests/integration/components.test.mjs` now covers version history and live collaboration for fields in a repeatable component and in a dynamic zone, and the reviewer's 404 for a zone it cannot read; it fails against 2.2.0 (404 for `sections.0.body`) and passes with 2.3.
- CONTRIBUTING.md did not describe what the 2.3 suites need from the host (LanguageTool private URL flag and the `MEX_LT_PRIVATE=false` run, the SDK example block, `grammar.use`, the `writer` admin).

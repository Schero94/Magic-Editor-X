Build under test: branch `feat/collab-2.1`, packed with `npm pack` (the package version stays 2.0.0 until semantic-release sets 2.1.0) and installed from the tarball into isolated Strapi 5.61.1 hosts: 1431 (SQLite), 1432 (PostgreSQL 16), 1441 (a database written by 1.5.1, upgraded straight to 2.1), and the 8-process cluster on PostgreSQL. Random `.env` secrets per host, outgoing network blocked in every Strapi process (`-r block-egress.cjs`), synthetic admins and content only. The AI provider is a local fake server.

## Soak

Six real collaboration clients (one Node process) edited one 41-block field (paragraphs and a table) for 30 minutes, about 23 updates per second in total, adding and removing text so the visible document kept its size. Server RSS was sampled with `ps` and the client heap after a forced GC every 30 seconds.

| Run                               | Edits  | Converged | Server RSS (first third → last third, max) | Client heap, 6 replicas (first third → last third, max) |
| --------------------------------- | ------ | --------- | ------------------------------------------ | ------------------------------------------------------- |
| 1 (SQLite, before the undo cap)   | 42,066 | yes       | 217.3 → 233.3 MB, max 249.1 MB             | 32.9 → 107.0 MB, max 123.5 MB                           |
| 2 (PostgreSQL, with the undo cap) | 42,216 | yes       | 231.9 → 258.7 MB, max 271.8 MB             | 33.0 → 108.9 MB, max 125.4 MB                           |

Findings: run 1 showed that the per-user undo history kept every step; it is now capped at 200 steps (`fix: cap the per-user undo history …`), which halves the growth in a single-replica benchmark (20,000 edits: +28 MB → +10 MB). The remaining growth is linear in the number of edits and comes from Yjs itself: a Y.Doc keeps metadata for every insert and delete (tombstones) for as long as the document lives. Measured: about 0.3 KB per edit per client (it holds two copies, the shared state and the shadow) and about 0.6 KB of server RSS per edit; nothing grew that was not proportional to the edit history. A room starts from a fresh document again `collaboration.roomTtlMinutes` after the last person left, which resets this. In a browser (one replica) a 30-minute session of six people typing continuously adds roughly 13 MB; a 2,000-block document uses about 90 MB of JS heap in Chromium.

The three checks reported as script problems in the 2.0 run were re-run: the import report (now passing), the tooltip markup (the check now accepts the leading space the selection includes) and the link preview card, which turned out to be a real bug: Enter in the link-preview and image-URL fields also created an empty block. Re-running the 2.0 gates on this build also found and fixed: version history restored the live state itself because automatic versions were taken seconds after typing started (now at the end of each period), and resyncs re-rendered the user's own blocks, which closed open inline tool panels.

### 2.1 additions

`s-addendum` (12 / 12 on the upgraded 1.5.1 host): the Content Security Policy notice lists the blocked embed sources, the copy button puts the `strapi::security` snippet on the clipboard with a success toast, the notice has no overflow at 390 px, blocked embeds and external images show the placeholder with a "How to allow it" link and do not mark the form as changed, the internal-link picker finds an entry by title and inserts `<a href="/articles/<documentId>" data-mex-uid data-mex-document-id data-mex-locale>`, and the link survives the server sanitiser on save.

### Migration from 1.5.1

The 1.5.1 database (JSON strings, plain text values, nested lists, checklists, tunes, a component field, a single type, a second locale, Yjs-only snapshots, a custom block with a script in its SVG icon and template) upgraded directly to 2.1: 17 / 17. This gate found that opening 1.x content marked the form as changed (Editor.js normalises some 1.x blocks while rendering and the block-menu save reported it); fixed in `fix(admin): opening 1.x content no longer marks the form as changed`.

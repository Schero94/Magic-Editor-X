# Magic Editor X 2.1 security audit: live collaboration

Scope: the collaboration surface of 2.0.0 (`main` at e4e8249): `POST /collaboration/session`, the Socket.IO server (`server/src/services/collaboration.js`), the stores and leases (`services/store.js`), the shared Yjs mapping (`shared/ydoc.mjs`) and the admin client (`admin/src/editor/collab-client.js`, `components/EditorField`). Also re-checked: the AI rate limit (per process in 2.0) and the two features added in 2.1 that touch untrusted input (internal-link search, CSP detection). Method: threat model per message and actor (anonymous, admin without access, viewer, editor, a malicious editor with a modified client, another tenant's admin), code review, then tests: unit and property tests (`npm test`), the integration suite against Strapi 5.61.1 on SQLite and PostgreSQL, the 8-process cluster run and browser acceptance. Synthetic accounts and data only.

Threat model in short: a WebSocket peer can send any bytes in any order, replay or steal tokens, and claim any identity in the payloads it controls. An admin with update access is trusted to change the content of documents they can update, but not to change other documents, other fields, other people's presence, the server's memory or other admins' browsers.

## Residual risks

- An admin with update access can still replace or delete the whole content of a field they may edit (that is editing). Versions and the Content Manager's own history allow recovery.
- The server does not rewrite HTML inside rooms (a CRDT cannot be rewritten without new operations); it relies on sanitising at every sink: the editor before rendering, version history and the Document Service on save. A frontend that read room tables directly would bypass this; frontends read stored content only.
- Rooms are held in memory per process while someone is connected. Memory per process is bounded by the number of open rooms (capped per admin) and the room size limit (64 MiB of history).
- Text formatting is part of the text (HTML in a Y.Text): concurrent formatting of the same word can produce nested tags; they stay within the inline allow-list.
- Rate limits and caps are fixed-window or heartbeat based and can be exceeded briefly at window edges or while presence heartbeats are in flight.
- `rawHtml: 'allow'` stores raw HTML as typed; frontends must treat it as trusted.

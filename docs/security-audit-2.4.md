# Magic Editor X 2.4 security review: new surfaces

Scope: everything 2.4 adds or changes on top of 2.3.1 (`main` at 9c25472): field identities (`fieldKey`) for editor fields in repeatable components and dynamic zones and the mapping of rows stored by position, tables v2, math and footnotes, video and audio by URL, the `@` trigger and code file names, block-scoped AI and alt text from private image storage, the audit trail, versions of synced block sources, "Run now" and the time zone of the scheduled link check, comments on selected text, admin mentions, notifications and mention e-mails, block suggestions, the guard for Strapi's AI translations, Releases readiness and the published-status bypass of the publishing guard, and the collaboration data-loss fix. Method: threat model per surface and actor (anonymous, an admin without the plugin actions, a read-only reviewer, an editor, an editor with a modified client, an API client, a hostile stored value read by a frontend, a hostile AI provider or remote server), code review of the merged `feat/2.4` branch, then tests: unit and property tests (`npm test`), the integration suite against Strapi 5.61.1 on SQLite and PostgreSQL 16 (`tests/integration/*.test.mjs`, run by the feature agents against their own hosts), the multi-process cluster run and browser acceptance. Synthetic accounts and data only. Every test cited below was checked by name in `tests/` or `tests/integration/` at commit a10732d.

## Unchanged controls re-checked

RBAC on every new admin route (`admin::isAuthenticatedAdmin` + `admin::hasPermissions`; 18 new routes, three new actions `audit.read`, `suggestions.create`, `suggestions.review`, none granted to a role automatically), strict bounded zod schemas, Content Manager access through `services/access.js` with 404 for denied documents, no secrets in responses, no content, URLs with queries, user ids or e-mail addresses in logs. Dependencies: `temml` 0.14.0 added (MIT, maintained, no dependencies), `@editorjs/table` removed; `npm audit --omit=dev`: 0 vulnerabilities (2026-11-12). Every new content type (`comment-notification`, `suggestion`) is hidden from the Content Manager and has no Content API route; the audit table is not a content type.

## Residual risks

- A positional value emptied and saved becomes `null` and loses its key; its old versions and comments are no longer served (they stay stored). Discarding a draft whose published version predates 2.4 drops keys added to the draft. API writes that send positional values without key and without component `id` get new keys on every write.
- Unmapped legacy rows of deleted entries stay in the database; nothing deletes them.
- The media signature check confirms the container, not the codecs. Downloads are buffered in memory (bounded by `uploads.maxMediaBytes` and 3 per process).
- A listed private origin (`uploads.allowPrivateOrigins`, `ai.altText.allowPrivateOrigins`) can be reached on any path of that host by admins who can upload or use AI.
- Audit: writes around the Document Service are not recorded; global readers (`audit.read` + `settings.read`) see who changed which documents and fields, not what. Two extra reads of editor fields per write to types with editor fields.
- Mention e-mails are sent in English; the recipient's admin locale is not known to the server. Notification rows written around the Document Service are not cleaned up.
- Suggestions are block level; an accepted block replaces the whole block. Rows deleted around the Document Service leave orphans.
- The AI translation guard hooks Strapi's services registry (`strapi.get('services').extend`), which is public but not documented for this use. If a Strapi update renames or reshapes these i18n services, the guard stops working (a warning is logged when only one of the two services is found) and values are sent whole again. Translated text is only as faithful as the provider.
- Preset violations are not part of Releases readiness (every save already refuses them; a draft holds them only when a preset was tightened later).
- Review workflow stage changes are not checked by the plugin (see the README); deleting a stage moves entries with knex outside the Document Service.
- Synced-source version hashes do not ignore default tune values, so an unchanged re-save after an editor round-trip can store an extra version.
